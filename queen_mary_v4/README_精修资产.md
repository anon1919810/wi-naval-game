# HMS Queen Mary v4 · 模块化精修与剖视资产

本版基于 `f717c0c` 中的 v3 模型制作。目标是更完整的舰船外观，以及用于剖视和损伤展示的内部结构；不提供可步行舰内空间。原 v3 和 Unity 游戏工程保持原状。

## 打开哪个文件

| 文件 | 用途 |
| --- | --- |
| `QueenMary_v4_Full.blend` | 完整外观。内部与损伤代理默认隐藏，避免干扰外观浏览 |
| `QueenMary_v4_Cutaway.blend` | 右舷半侧被移除的剖视展示副本，内部设备保留完整以便阅读 |
| `QueenMary_v4_Exterior.fbx` | 完整外观导出，保留炮塔/俯仰/炮管/炮口层级 |
| `QueenMary_v4_Interior.fbx` | 独立内部视觉资产，按模块 ID 与原损伤模块对应 |
| `queen_mary_v4.py` | 单文件可重复生成脚本；不依赖原仓库脚本、不下载模型或贴图 |
| `previews/` | 全舰、侧面、舰桥炮塔、舰艉、全舰剖视、弹药库和机炉舱预览 |
| `textures/` | 随脚本生成的底色、法线及 Metallic/Smoothness 贴图；不含第三方购买资源 |
| `interior_modules.json` | 14 个内部视觉模块与原损伤模块的对应表 |
| `object_manifest_v4.json` / `created_objects.txt` | 对象名称、角色、尺寸、位置、父级和三角面统计 |

## 本轮修改

- 保持船体长 213.4 m、宽 27.2 m、吃水 9.9 m；细分站位并采用单调插值改善曲面连续性，型值仍是估算。
- 保留 A/B/Q/X 布局、三烟囱与圆形中烟囱、16 门副炮、舰艉阳台、防雷网撑杆和早期单杆桅。
- 分层舰桥与支柱、门窗、扶梯、通风筒、系缆桩、锚链、艇具与吊艇杆、烟囱爬梯、炮塔表面细节、成形螺旋桨。
- 钢板涂装、木甲板、水下漆、深色金属、帆布、内舱涂装与设备材质；纹理由脚本生成并打包进 Blender 文件。
- 四座炮塔保持可旋转层级，八根炮管各有独立 `Muzzle_<炮塔>_<Port/Starboard>` 炮口节点。
- 4 个弹药库、7 个锅炉舱、2 个轮机舱、1 个舵机舱的简化设备；增加内部甲板、肋骨、舱壁、炮座围筒和输弹竖井示意。

## 分层与模块化

Blender Outliner 中有五个资产集合：

1. `01_Exterior`：外部可见模型。
2. `02_Interior_Visual`：内部设备、舱室和结构展示。
3. `03_Damage_Proxies`：继承的逻辑舱室体积，默认不渲染。
4. `04_Armour_Proxies`：装甲代理，默认不渲染。
5. `05_Functional_Anchors`：模块根节点、炮口与功能锚点。

`90_Preview_Only` 中的摄影棚、灯光、地面和相机不导出。完整模型中的内部集合默认隐藏；需要单独检查某舱时，在 Outliner 启用该集合和相应对象的视图/渲染可见性。直接看整体剖视建议打开 Cutaway 文件。

设备网格使用 `module_id` 对应 `Magazine_A`、`Boiler_Room_1` 等既有模块。视觉设备不能直接替换损伤体积或装甲碰撞。静态细节按职责合并，炮塔与炮管运动链保持独立。

## 推定范围与资料说明

用户确认“18”为图片编号，本版不把它解释为年份。参考为已提供线图与黑白照片；没有新获得的精确型线、各层舱室总布置或机炉舱设备图。

本版 `historically_certified=false`。船体站间曲线、涂装色值、具体甲板设备、内部甲板/舱壁、锅炉外形与排列、轮机外壳、输弹机构及弹药架均为建模推定。内部用于表达模块关系和剖视阅读，不能作为原舰工程图、弹药库存数量或管路布置证据。已有资料不足以保证每个设备的位置与原舰一致。

## 验证与性能口径

构建器执行 13 项几何/结构检查。独立验证器重新打开两份 Blender 文件，并分别清场导入两份 FBX，检查尺寸、炮口父链、模块对应、UV、材质图像、代理分层和导出身份。另在同一 Blender 进程中连续生成两次，比较完整网格与层级的签名。

具体结果以 `verification_v4.json`、`verification_v4_independent.json` 和 `repeat_verification.json` 为准。当前外观导出约 8.37 万三角面、64 个网格；内部约 9.72 万三角面、15 个网格。内部默认隐藏。全舰附件含副炮突出部分，整体包围盒宽度约 32.1 m；27.2 m 指舰体宽度。

这是新精修资产，并未给 v4 生成/验证新 LOD，也未替换当前 GameplayLab 的 v3 Prefab。没有本轮 Unity 实机导入、运行时朝向或多舰性能通过的结论。64 个网格也不等于 64 次绘制调用，多材质会影响实际渲染成本。

## Unity URP 接入说明

- 外观、内部分别导入，并共用同一个舰根变换；采用与 v3 相同的 FBX 导出轴处理。实际 Unity 导入后仍要检查 +Z 艏、+Y 上及 1:1 尺寸。
- 为各材质建立 `Universal Render Pipeline/Lit`。`*_BaseColor.png` 设为 sRGB；`*_Normal.png` 设为 Normal Map；`*_MetallicSmoothness.png` 关闭 sRGB，R 为金属度、Alpha 为光滑度。
- 使用 `material_manifest.json` 中的常量和贴图路径映射。FBX 不会自动把所有 Blender 节点转换成正确的 URP 材质，不应只凭 FBX 导入成功判断材质接入完成。
- `Muzzle` 节点的 Blender 局部前向为 +Y，运行时需验证导入后的局部轴，不能直接假设它等于 Unity `Transform.forward`。
- 接入损伤时按 `module_id` 绑定已有系统。内部展示不能修改损伤真值；剖视副本不能作为完整舰体碰撞资产。

## 重建

使用 Blender 4.5 LTS 运行：

```powershell
.\rebuild_v4.ps1 -BlenderExe '完整路径/blender.exe'
```

只更新资产和报告、跳过预览：加 `-SkipRender`。该选项不会更新已有预览；脚本不会把旧图片当成本次新渲染证据。

也可在 Blender Text Editor 打开 `queen_mary_v4.py` 执行。脚本会清理当前场景；推荐在新文件中运行。运行后保存完整模型与剖视模型，打印全部资产对象名称及尺寸。

不要只改 `.blend` 后期望下次构建保留。造型、材质和模块调整应回写生成脚本。
