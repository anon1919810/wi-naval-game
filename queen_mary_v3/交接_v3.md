# v3 接续说明

当前交付目录为 queen_mary_v3，基于 DeepSeek 修改后的桌面 queen_mary；旧文件夹不覆盖。
用户最终选择早期照片的单杆桅方案，已覆盖先前的双三脚桅选择。

全部 98 个原资产对象及其父子层级保留，仅增加三个合并装饰对象。船体截面补回右侧平板龙骨点；参数接口继续有效。
炮管原点现在分别位于各自耳轴，不依赖额外 Muzzle 节点。未来取炮口可用每根炮管局部 +Y 12.4 m，Unity 转换约定见 README。

实际对象/三角面和验证以 object_manifest.json、integration_verification.json 为准。Unity 报告已重新生成并与本次 FBX 哈希绑定，旧 v1 报告不再引用。
原交接对装甲件数有误：原脚本及当前脚本实际均生成 8 个 armour_* 网格，另有 14 个损伤体量。63 个外部网格只满足当前数量预算，不等于实际帧率结论。

本轮未改装甲厚度、舱室估算站位或火控数值。后续优先取得高分辨率型线/装甲原图，再校准数据；然后在独立海战工程中完成 URP 材质、损伤碰撞器、LOD 与多舰性能测试。

最终基线已追平桌面 21:27 的最新生成器：轮机舱避重叠调整、系统关系、命中区、渗透率、材质规格和五份数据输出均合入。水线面 Simpson 积分中点半宽遗漏乘 2 已修复，并以线性站位宽度的精确积分独立复核。

FBX 导出前绕 Z 转 180°，导出后恢复源 .blend。Unity 使用 UseFileScale=false、BakeAxisConversion=false；本次四座炮塔实测为本地 +Z 偏航和本地 +X 俯仰、正角度。旧版负号不适用于当前组合。已用原有 Naval.ShipContractData 实际反序列化新契约并核对所有模块。

桌面 unity_integration 保持原样；旧同步脚本仍读取 queen_mary/_Greybox.fbx，使用 v3 时需改为本目录和新文件名。独立验证工程需要 Unity 内置的 com.unity.modules.jsonserialize；本次已补齐并验证。

## 后续（2026-09-18，本仓库融合之后）

> 以上是 v3 那一侧的接续说明，保持原样。以下是把它接进 Unity 之后的追加记录。

- **仓库**：`HMS_Queen_Mary_建模成果_2026-09-17/` 于 2026-09-18 建 git 仓库。v2 / v3 先原样入库做
  基线，**融合动作本身是一次可审阅的 diff**。此前历史无法重建，从那一刻起才有记录。
- **Unity 集成只有一个家**：`queen_mary_v3/unity/`（`Editor/` + `Scripts/`）。原来那份并行的
  实现归档在 `docs/legacy_codex_unity/`，**不要拷进工程**（同名 `ShipContract` 会撞出 CS0101）。
  它里面有两条比我们强的检查已并进 `ShipAssetValidator`：**物理右舷方向**
  （`Casemate_Starboard_1 − Casemate_Port_1` 必须朝 Unity +X，实测 `(1, 0, 0)`；
  船体左右对称，只有带左右标注的点能判出左右手性）与**逐炮塔轴表**（A/B/Q/X 各自的轴与符号）。
- **同步脚本已重写**：旧版还指着融合前的 `Assets/…` 路径、FBX 名写死 `*_Greybox.fbx`，
  **照跑直接抛错**。现在 `.cs` 整目录拷、FBX 名从契约 `file_refs.fbx` 读。
- **运行时船体已做**：仅碰撞层（24 个内部网格关渲染，draw call 85 → 61）、13 个舱室挂
  trigger 盒碰撞体并带上浮力数据、LOD0–3、`ShipDefinition` ScriptableObject。
  见 `unity/README_集成.md` 第八节。
- **一处订正**：v3 把炮管原点放在各自耳轴上（`(±1.25, 0, 0)`）是**对的**。我们原来那条
  "炮管原点必须在父节点原点"的断言，把 v2 的实现细节当成了契约，已改为物理不变量：
  **原点允许沿耳轴偏移，垂直于耳轴的两个分量必须为 0**（否则抬炮口会绕错圆心）。
- **一处契约缺口**：`ship_contract.unity.json` 的 `file_refs` 里**没有 `buoyancy_compartments.json`**，
  而 `ShipRuntimeBuilder` 必需它。同步脚本暂时显式带上；理想情况是 Blender 侧生成契约时补一行。
- **仍未做**：LOD2/LOD3 的像素证据、船体级碰撞代理（现在是舱室盒体 trigger，没有整船凸包）、
  射界精度升级、15 艘同屏的真实帧率压测。
