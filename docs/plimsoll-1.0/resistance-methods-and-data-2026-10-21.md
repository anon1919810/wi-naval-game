# 阻力计算方法与数据计算报告

生成：2026-10-21 ｜ 分支 feature/plimsoll-1.0 ｜ 对应提交见文末

本报告汇总 plimsoll 现阶段"算功率"的全部计算链、公式、数据来源与实测结果，并把审查中发现的
口径缺陷一并写清楚 —— 因为在这套体系里，**口径错误比模型误差大**。

## 怎么用（先看这张表）

| 你手上是 | 走哪个模式 | 代码怎么写 | 会得到什么 |
|---|---|---|---|
| **额定值**（设计功率/设计航速，公开资料、舰种表、合同书） | **design mode** | `"target_mode": "design"` + `"calibration": {"mode": "design"}` | 功率乘 **0.8079**（n=27，嵌套 LOOCV 10.56 %，未校正 23.04 %），结果对标"设计意图" |
| **试航实测值**（试航报告、measured mile） | **trial mode**（缺省） | 不写 `target_mode`；集群船可加 `"calibration": {"mode": "cluster", "design_speed_kn": …}` | 不做全局缩放；集群内乘约 0.85（n=8，LOOCV 9.16 %） |
| 只有额定值、想知道实际能跑多少 | design mode + 梯子换算 | 用 `trial_dataset.rated_ladder()` | 实测/额定 = **×1.126**（0.986–1.424），航速 **+2.86 %**（中位，n=27），带区间 |

三条硬规矩：

1. **不要混**：集群校正（0.851）是拿试航数据拟合的，套到额定值上会双重惩罚 —— 代码里会直接拒绝（`calibration.mode_conflict`）；
2. **报数必须标模式**：本文第 1–22 节的全部百分比都是 **trial mode**；第 23–24 节才有 design mode 的数字；
3. **0.8079 与 0.851 都是小样本点估计**（n=27 / n=8），带 ±0.05 量级不确定性，不要当定值对外。

## 0. 摘要

- 同一批 146 条历史案例：原程序口径 MAPE **15.93 %**，Holtrop **12.94 %**，按船型混合 **11.86 %**，
  混合 + 按舰种因子（嵌套留一法）**10.62 %**。
- 五条带出处的试航对照：Dreadnought **+9.27 %**、Bismarck **−0.43 %**、Repulse **+20.06 %**、
  Renown **+25.92 %**、Hood **+22.45 %**（n=5，MAPE 18.19 % → 修正载况后重算见 §7.3）。
- 三个"口径级"发现，都比模型改进更值钱：
  1. 长度基准 LOA→LBP 让 Hood 的误差从 +24.73 % 变 +35.27 %（**10 个百分点**）；
  2. 载况混用（deep 排水配试航功率）让 Hood 从 +35.27 % 回到 +22.45 %（**13 个百分点**）；
  3. 146 条参考集**混用设计额定值与试航值**，Dreadnought 一条就差 3.7 个百分点。

## 1. 单位与符号

**约定**：一切计算走 SI；原始出处的数值保留原单位与出处；只在边界换算一次。
数据集里逐条记录 length_basis（lbp/loa）与载况说明。

| 符号 | 含义 | 单位 |
|---|---|---|
| L_BP / L_OA | 垂线间长 / 全长 | m |
| B | 型宽 | m |
| T | 吃水 | m |
| ∇ | 排水体积 = Δ/1.025 | m³ |
| Δ | 排水量 | t |
| Cb, Cp, Cm, Cwp | 方形、棱形、中横剖面、水线面系数 | – |
| S | 湿表面积 | m²（老口径为 ft²） |
| V | 航速 | kn；Vs = 0.514444·V m/s |
| Fr | 弗劳德数 = Vs/√(gL) | – |
| Re | 雷诺数 = VsL/ν，ν = 1.19e-6 m²/s | – |
| R_T | 总阻力 | kN |
| P_E | 有效功率 = R_T·Vs | kW |
| QPC | 准推进系数 | – |

## 2. 计算链 A：原程序口径（SpringSharp 血统，经验回归）

实现于 tools/plimsoll/concept_estimates.py，逐行对应原 C# 的 HullControl / EngineControl。
**内部是英制**（ft、长吨、ft²），这是它的历史包袱，不是我们的选择。

1. 船型系数
   co = 0.4 × (6B/L)^(1/3) × √(Cb / 0.52)

2. 有效长度（按艉型分支，STERN_TYPES 的索引）
   - 巡洋艉（index 2）：L_eff = B/co + L
   - 小型方尾（index 1）：L_eff = 0.5B/co + L
   - 其余：L_eff = L

3. 湿表面积
   S = 1.7·L·T + 35.0·Δ/T  （单位 ft²，Δ 为长吨；35.0 是海水每长吨立方英尺数）

4. 功率长度（分段，注意 V≤15 时取 2L − L_eff）
   - V ≤ 15 kn：L_hp = 2L − L_eff
   - V ≥ 25 kn：L_hp = L_eff
   - 其他：L_hp = (L_eff − L)·(V − 20)/5 + L

5. 轴马力
   P = [ Δ^(2/3)/L_hp · co · V⁴  +  0.01·S·V^1.83 ] · V / 184.1666667
   - 第一项为兴波项（与 V⁴ 成正比）
   - 第二项为摩擦项（与 V^1.83 成正比）
   - 184.1667 是原程序的单位换算常数（lb·ft/s → hp）
   - 年份修正：engine_year < 1890 时 ×(1 + (1890 − year)/100)

6. 分项（用于报告摩擦/兴波占比，兴波用 L 而非 L_hp）
   R_friction ∝ 0.01·S·V^1.83 ；R_wave ∝ Δ^(2/3)/L · co · V⁴

**特性**：纯经验，无 Fr 域限制、无 Cb 上限、无 Cp 依赖。所以在 32 kn 的细长战巡上会系统性高估
（§7.3 里三艘英战巡 +20~26 % 就是这条链给出的）。

## 3. 计算链 B：Taylor-Gertler 严格源轴

实现于 tools/plimsoll/resistance.py（speed_power_curve），**纯 SI**。

1. 摩擦（默认 ITTC-57，可选 Schoenherr 隐式）
   Cf = 0.075 / (log10 Re − 2)²
   Rf = ½ ρ S Vs² Cf ，ρ = 1025 kg/m³

2. 剩余阻力（源表插值，索引为 Cp × B/T，按体积比修正）
   Rr = Cr(Cp, B/T, ∇/L³) · ½ ρ S Vs²

3. 严格模式（taylor_gertler_source_axis_strict）
   - 四个插值角点的权重必须齐全，**缺角直接拒绝**，不做重归一（诊断 taylor.speed_unavailable）
   - 域：Fr 0.16–0.58；表外端点截断并告警，不外推

4. 功率
   R_T = Rf + Rr ；P_E = R_T·Vs ；轴功率 = P_E / QPC

## 4. 计算链 C：Holtrop-Mennen 1982

实现于 tools/plimsoll/holtrop.py，SI。**与本仓库无关的独立 Rust 实现在同船同系数下核对过**（§8.1）。

1. 湿表面积（回归式，可直接用几何积分面积覆盖）
   S = L(2T + B)√Cm · (0.453 + 0.4425Cb − 0.2862Cm − 0.003467·B/T + 0.3696Cwp) + 2.38·A_b/Cb

2. 形状因子
   L_r = (1 − Cp + 0.06·Cp·lcb/(4Cp − 1))·L
   1 + k₁ = c13 · [0.93 + c12·(B/L_r)^0.92497 · (0.95 − Cp)^(−0.521448) · (1 − Cp + 0.0225·lcb)^0.6906]
   （c12 由 T/L 分段给出；c13 由艉型系数 c_stern 给出）

3. 摩擦
   Rf = ½ ρ S Vs² Cf ，Cf 同 ITTC-57

4. 兴波
   R_w = c1·c2·c5·∇·ρ·g·exp[ m1·Fr^(−0.9) + m4·cos(λ·Fr^(−2)) ]
   c1 = 2223105 · c7^3.78613 · (T/B)^1.07961 · (90 − i_E)^(−1.37565)
   i_E = 1 + 89·exp{ −(L/B)^0.80856 · (1 − Cwp)^0.30484 · (1 − Cp − 0.0225lcb)^0.6367 · (L_r/B)^0.34574 · (100∇/L³)^0.16302 }
   c7：B/L < 0.11 时 0.229577·(B/L)^(1/3)；B/L > 0.25 时 0.5 − 0.0625·L/B；其余取 B/L

5. 其他项
   R_app（附体，按面积×Cf）、R_b（球鼻）、R_tr（方尾）、R_bto（艏推）、R_a（相关补贴，默认 0.04 系数或粗糙度增量）

6. 总阻力
   R_T = Rf·(1 + k₁) + R_app + R_w + R_b + R_tr + R_a + R_bto

## 5. 混合规则（第 3 步成果）

按**船型**而非航速给权重，因此沿功率曲线不会跳变：

    w_H = 1 / (1 + exp((Cb − 0.50) / 0.035))
    R_T = (1 − w_H)·R_T,TG + w_H·R_T,H

- Cb 0.44（驱逐舰量级）→ w_H ≈ 0.85；Cb 0.56（战列舰量级）→ w_H ≈ 0.15
- 只有一侧有结果时：取该侧，标 blended=false 并写明原因，**不冒充两模型一致**
- 连续性：0.001 的 Cb 步长下权重变化 < 0.02（有专门用例）
- 拟合版（可选，不设为默认）：z = −20(Cb − 0.5) − (B/T − 3) + 1；嵌套 LOOCV 11.51 % 对默认规则 11.86 %，
  只值 0.35 个百分点，故保留为选项

## 6. 校准因子（第 4 步成果）

定义（比值总和，而非平均比值）：

    k_type = Σ ref / Σ pred

应用：P_cal = k_type · P；结果行附带 factor / sample / LOOCV / 出处，未覆盖的舰种**直接拒绝**。

| 口径 | 战列舰 | 航母 | 巡洋舰 | 驱逐舰 |
|---|---|---|---|---|
| 原程序 | 0.923 | 0.970 | 1.020 | 0.816 |
| 混合后 | 0.924 | 0.963 | 1.056 | 0.979 |

嵌套留一法（每条船的因子用其余 n−1 条重拟合）：原程序 15.93 % → **12.11 %**；混合 11.86 % → **10.62 %**。

## 8. 审查结论（对现有代码与数据的独立复核）

1. **算术一致**：用独立脚本重算五条案例，co、L_eff、S、P、误差逐条与数据集吻合（差 < 0.05 点）。
2. **载况混用已修**：Hood 原用 deep 排水 47,429 t 配试航功率，改为试航排水 42,200 t，误差 35.27 % → **22.45 %**。
   数据集新增 condition_note 与 sensitivity_pct 字段，把这种混用记录在案而不是藏起来。
3. **长度基准已记录**：全部改用 LBP，并在文件里写明 length_basis；LOA 会让 Hood 少算 10 个百分点。
4. **抓取管线只能给设计值**：36 条里按"句子里自称试航"的闸门自动通过仅 3 条，其余需人工核读。
5. **剩余近似**：Cm/Cwp 在 Holtrop 侧仍用 0.95 与 (1+2Cb)/3；146 案例的 QPC 仍是一个全局 0.440。

## 9. 有了数据之后：还要不要再做修正因子？

分三步判断，不要一上来就拟合。

**第一步：看误差的形状，而不是均值。**
现在 5 条试航里，Bismarck −0.43 %，三艘英战巡 +20~26 %。误差不是均匀散布，而是**跟着船型走**。
若 20–30 条数据仍是这个形状，那么"一个全局因子"就是在平均掉一个本该分段的偏差 —— 这正是第 3 步混合规则要解决的。

**第二步：先分段，再看残差。**
按 (Cb, Fr) 把船分组，比较组内残差的均值与离散：
- 若各组残差均值显著不为零且方向一致 → 该组需要一个**分段常数**；
- 若组内离散远大于均值偏移 → 再校准也压不下去，问题在模型形式（该换方法或补物理项）。

**第三步：要因子就做成分段的，并只做"最后的一致性校正"。**
判据：分段后残差均值的绝对值 < 组内标准差的一半时，不再上因子（否则是拟合噪声）。
一律用**嵌套留一法**评分，并同时报中位数与区间，不能只报 MAPE 单点。

**结论**：**先分段、后因子**。混合规则已经在做"按船型选方法"这件事，因子只应处理剩下的常数偏差，
而且必须是分段的、带样本量的、可拒绝的（现在的 resistance_calibration 就是这个形态）。

## 11. 已知缺陷与未完成

1. 试航样本 **n=5**，且四艘是英国船、集中在 30–33 kn 段，不足以支撑按舰种 LOOCV；
2. 载况记录不全：Hood 的吃水仍是 deep 值，Repulse/Renown 的试航排水未核；
3. Holtrop 侧 Cm/Cwp 用近似式，未用几何或声明值；
4. 146 案例的 QPC 是全局 0.440，把阻力误差与推进误差混在一起；
5. 146 条参考集未按"设计/试航/未知"清理 —— 所有百分比目前只能叫"相对参考的误差"。

## 12. 试航数据集扩建（第 2 轮：从 5 条到 9 条）

按"两端取样"扩表：慢速战列舰补了 3 条（Orion 21.3 kn、Monarch 21.9 kn、Ise 23.6 kn），另加扶桑 23.0 kn。

### 读数结论（每条都是逐句读出来的，不是正则直接落盘）

| 舰 | 原文 | 判定 |
|---|---|---|
| HMS Tiger | "designed to produce 85,000 shp … but only **achieved 104,635**" | ❌ 机器抓的是设计值，未收 |
| HMS Lion | "designed to produce 70,000 shp, but achieved more than 76,000 during her trials" | ❌ 设计值，未收 |
| HMS Revenge | "rated at 40,000 shp and **intended** to reach 23 kn" | ❌ 设计值，未收 |
| HMS New Zealand | "produced **over** 49,000 shp" | ⚠️ 下界 + 只有 LOA，暂缓 |
| HMS Barham | 1933 年改装后测速 22.5 kn / 65,655 shp | ⚠️ 条件特殊，存疑未收 |
| **扶桑** | "exceeded her design speed of 22.5 kn …, reaching **23 kn at 46,500 shp**" | ✅ 收（注意配对是 23 而非 22.5） |
| **Orion / Monarch / Ise** | "reached a maximum speed of 21.3 kn from 30,552 shp" 等 | ✅ 收 |

### 结果（n=9）

| 口径 | MAPE | 中位 | 区间 |
|---|---|---|---|
| 全部 | **10.89 %** | 9.27 % | −10.94 % … +25.92 % |
| 战列巡洋舰（3） | 22.81 % | 22.45 % | +20.06 % … +25.92 % |
| 战列舰（6） | 4.92 % | 4.08 % | −10.94 % … +9.27 % |
| ≥30 kn（4） | 17.21 % | 21.25 % | −0.43 % … +25.92 % |
| <24 kn（5） | **5.82 %** | 5.46 % | −10.94 % … +9.27 % |

### 最重要的新发现：误差在两端**变号**

- 31.7 kn 以上的战巡：**全部高估 +20 … +26 %**；
- 21.3–23.6 kn 的慢速战列舰：**全部低估 −0.8 … −10.9 %**（Dreadnought 的 +9.27 % 是唯一例外，
  且它是这批里唯一用 deep 吃水配正常排水的条目）。

也就是说，误差不是"整体偏大"或"整体偏小"，而是**随航速/细长度改变符号**。
这直接说明：任何全局常数因子（包括 0.924）都是在平均一个**穿过零点**的结构，
它的数值会随样本里快慢船的比例漂移 —— 这是"先分段、后因子"最硬的实测依据，比之前 146 条案例的间接证据更直接。

### 记录方式

- 三条新数据都只有**全长**（页面未给垂线间长），已在 `hull.length_note` 里写明"约 2–3 % 偏乐观"；
- Ise 另一条 25.3 kn / 81,050 shp 是**改装后**的试航，未混入；
- 校验器与测试保持 10 例通过，数据集 n=9。

## 17. 数据集第一次反哺模型（第 7 轮）

前六轮都是"改进数据集"。这一轮做了第一件相反的事：**用干净数据判断该用哪个方法，然后把结论写进模型。**

### 24 条试航案例上的 A/B（统一 QPC 0.444，使全队总轴马力等于总试航值）

| 群体 | n | 原程序口径 | Holtrop |
|---|---|---|---|
| 全部 | 24 | 11.13 % | **10.24 %** |
| 战列巡洋舰 | 10 | 18.77 % | **9.61 %** |
| 战列舰 | 9 | **5.57 %** | 12.35 % |
| 轻巡 | 4 | 3.12 % | **2.67 %** |
| **集群（L≥200 m、Cb≥0.49、Fr≥0.30）** | 8 | 15.03 % | **7.17 %** |
| 其余 | 16 | **9.17 %** | 11.78 % |

**结论**：集群里 Holtrop 把误差砍掉一半；集群外反而更差。而现行混合规则（只看 Cb）给战巡的 Holtrop 权重只有 ~15 %，
**正好反了** —— 这就是它在 24 条上只有 11.08 %（几乎等于不用混合）的原因。

### 新规则：三条件的平滑与

```
share_H = 0.05 + 0.90 · σ((L−200)/12) · σ((Cb−0.49)/0.015) · σ((Fr−0.30)/0.010)
```

三条条件相乘，因此**必须同时满足才会移交**；每一项都是 sigmoid，所以对每个参数都连续，
且权重只由船型决定、与评估航速无关（同一条船沿功率曲线权重不变）。

参数用 20 组（5 种宽度 × 4 组端点）粗网格在 24 条上选出，再用**逐条留出重跑搜索**验证：

| 口径 | MAPE | 中位 |
|---|---|---|
| 原程序口径 | 11.13 % | 5.40 % |
| Holtrop 单独 | 10.24 % | — |
| 现行 Cb 单参数混合 | 11.08 % | — |
| **三条件集群混合（嵌套 LOOCV）** | **9.24 %** | **6.43 %** |

基准（in-sample 调参）是 9.12 %，留出后 9.24 % —— 搜索空间很小，**没有过拟合的迹象**。

### 两个诚实的限定

1. 宽度是在这 24 条上选的，虽然过了留出验证，但样本量只有 24，不能当成"通用最优"；
2. **Invincible（171 m）被规则拒之门外** —— 她是战巡，但长度在 200 m 线下，权重只有 0.11。
   这是**有意的**：判据讲的是集群，不是舰种标签。测试里专门有一条断言她必须留在外面。

新规则目前只是 `resistance_blend.holtrop_share_cluster` 这个函数 + 6 条测试，
**还没有接进阻力阶段**（阶段里仍是 Cb 单参数版）。下一轮接进去并在 146 条案例上复核，看它是否同样成立。

## 20. 第 10 轮：把"只有集群需要因子"落成代码

### 新增 `resistance_calibration.cluster_factor`

```
share   = holtrop_share_cluster(Cb, L, Fr)        # 与混合规则共用同一个函数
weight  = clamp((share − 0.05) / 0.90, 0, 1)      # 归一化，端点能取到满值
factor  = 1 + weight · (0.851 − 1)
```

- **共用同一个集群判据**：混合规则与校准规则不可能各自漂移；
- **淡入而不是阶跃**：190→220 m 之间因子单调平滑变化，测试断言相邻步差 < 0.15；
- **带证据返回**：每次调用都返回 sample=8、LOOCV 9.16 %、未校正 15.03 %、出处路径。

第一版忘了归一化，导致连"深在集群里"的船也只能拿到部分修正（Hood 0.884 而不是 0.851）——
已修正为归一化后取端点，并加了"深在集群内必须取满值、Hood 这类边缘船取大部分"的两段断言。

### 为什么它取代按舰种那张表

按舰种因子是**标签驱动**的：同一"战列舰"标签下的船被同一个数缩放，不管它跑多快、有多长。
第 19 轮已经证明这在数据上不成立（战列舰因子无效、战巡因子有效，而两者同属"主力舰"）。
新的集群因子是**形状驱动**的，并且只在数据支持的那一段生效，外面自动趋近 1.0。

旧表暂不删除（仍可被 `apply_calibration` 引用），但在模块注释里标明"已被试航数据取代"。

### 本轮没做到的事：集群样本没能扩到 12 条

试了六艘德日战巡（Derfflinger、Seydlitz、Moltke、Von der Tann、Hindenburg、Kongō）：
**维基正文里没有一条"自称试航"的功率句**（都是额定值或缺失）。所以集群仍是 8 条，
0.851 这个数仍然建立在小样本上 —— 这一点不粉饰。

### 现状

- 阻力/校准相关测试 **29 例通过**；
- 数据集 n=29；
- `cluster_factor` 尚未接进阻力阶段（阶段里仍需显式声明），下一轮接入并复核。

## 21. 第 11 轮：把集群校正接进阻力阶段

### 接线方式

场景里声明即可：

```json
"calibration": { "mode": "cluster", "design_speed_kn": 28.5 }
```

- 因子用**设计点**算一次，整条曲线共用一个值（测试断言：曲线上因子唯一）；
- 每次调用返回 `sample / loocv_mae / uncorrected_mae / source`；
- 缺 `design_speed_kn` → 阻断级 `calibration.missing_design_speed`；
- 缺 `hull.block_coeff` → 阻断级 `calibration.missing_form`（不猜船型，也就不会误用校正）；
- 集群外的船因子自动趋近 1.0（测试用 Cb 0.40 / 21 kn 的船验证）。

### 顺手修掉一个双路径导入问题

`resistance_calibration` 里 `from . import resistance_blend` 在测试直接以顶层模块导入时会炸
（`attempted relative import with no known parent package`）。改成 try/except 双路径，
与 `_analysis_resistance` 的既有做法一致。这个错误一次让 15 个用例变红 —— 说明测试网是有效的。

- 阻力/校准/混合相关测试 **44 例通过**；
- 全量核心套件已在后台重跑（上一轮 2,634 passed + 4,852 subtests / 719 s），结果下一轮报；

## 22. 收尾：这批数据支持什么、不支持什么（第 12 轮）

### 交付物

| 项 | 内容 |
|---|---|
| 数据本体 | `tools/plimsoll/cases/trials/dataset.json` —— **29 条**，全部 `hand_checked`（每条都逐句读过原文） |
| 校验器 | `tools/plimsoll/trial_dataset.py`：五道闸门（引文、试航类型、载况、长度基准、合理性带）、去重、按舰种/航速/Fr/Cb/长度基准五维统计 |
| 说明 | `cases/trials/README.md`：字段表、五条硬规矩、当前统计、加数据流程 |
| 测试 | 数据集 11 例 + 阻力/校准/混合 44 例 |
| 模型侧产出 | `holtrop_share_cluster`（三条件分流）、`cluster_factor`（集群水平校正），均已接入阻力阶段（可选） |

### 数据支持的六条结论

1. **误差不是常数偏差，符号随船型/航速段改变**：31.7–32.6 kn 的战巡全部高估 +2…+32 %，
   21–23 kn 的慢速战列舰多数在 −13…+21 % 之间摆动，Fr≈0.42 的轻巡反而低估 1–4 %。
2. **全局常数因子有害**：29 条上 11.17 % 对 11.08 %（有因子更差）。
3. **只有"快—大—肥"集群需要水平校正**：8 条上 0.851 使 LooCV MAE 从 15.03 % 降到 9.16 %；集群外上因子反而更差（10.21 对 9.58）。
4. **在集群里，水平校正比换方法更有效**：战巡 10 条上因子 7.01 % 对 Holtrop 9.61 % —— 偏差是水平而非形状。
5. **两次假设被新数据推翻**（31 kn 阈值、Cb 定符号），且都写进了测试的 docstring —— 数据集的真正价值在这里。
6. **146 条参考集与试航实测在集群外结论相反**（试航：原程序 9.17 % 好于 Holtrop 11.78 %；146 条：Holtrop 14.15 % 好于 17.91 %），
   因为前者混入设计额定值。**先修数据、再调模型**这条判断现在有实测支撑。

### 数据不支持的（必须讲清楚）

1. **集群样本只有 8 条**（战巡 10 条）—— 0.851 与 0.812 都有 ±0.05 量级的不确定性，不能当定值用；
2. **不是每轮都扩了表**：第 8、10、11 轮各新增 0 条，原因是两端来源枯竭（德日战巡维基正文无试航功率句、
   dreadnoughtproject 403、navweaps 不可达）。目标里"每轮 3–5 条"这一条**没有达成**；
3. **6 条以上只有全长**（LOA），比垂线间长乐观约 2–3 %，已逐条写在 `length_note`；
4. **没有任何一条经过档案原件核对** —— 全部是网页转录（维基正文、worldwar1.co.uk、kbismarck）。

### 下一步（按性价比排序）

1. **补集群样本到 15 条以上**：优先德方（Derfflinger/Seydlitz 验收记录）与日方（Kongō 级试航表），
   来源已知但需要读档案或专门的试航汇编，网页抓取已到极限；
2. **把 LOA 的 6 条换成 LBP**（英国海军部各舰《Ship's Cover》通常给出 pp 与 oa 两个值）；
3. **集群因子做区间而不是点估计**：n 到 15 后给出均值 ± 一个标准误，并在产品里按区间显示；
4. 在此之前，**不要把 0.851 设成默认**，也不要在宣传口径里把它说成"已验证精度"。

## 23. 额定值与试航值：两种目标，两套口径（回应"用户手里是额定值"）

这一条是被指出来的产品错位：**用户能提供的几乎总是额定（设计）值，不是试航实测。**

### 数据集补上 `rated` 块

29 条里 **27 条**现在同时带额定与试航两组值（各自带出处与引文）。同批船的对照：

| 统计量 | 中位 | 区间 | n |
|---|---|---|---|
| 试航功率 / 额定功率 | **×1.126** | 0.986 – 1.424 | 27 |
| 试航航速 − 额定航速 | **+2.86 %** | −1.38 % – +10.45 % | 27 |

极端例子：Canada（×1.424，23→24.3 kn）、Hyūga（×1.405）、Tiger（×1.231）；
反向的例子：Ceres（×0.986，试航略低于额定）。

### 由此必须分开的两件事

| 模式 | 参照 | 适用 | 我们目前的成熟度 |
|---|---|---|---|
| **design mode** | 额定值 | 用户输入、方案比较、报价 | 只有这 27 条对照，**未做校准** |
| **trial mode** | 试航实测 | 验证、复盘、真实性能 | 29 条 + 前 22 节的全部结论 |

**关键推论**：把 trial mode 的校正（0.851）套到额定值上，等于**双重惩罚** —— 用户的额定值本就比实测低约 11 %，
再乘 0.851 会把功率压到真值的 ~0.75。所以 `cluster_factor` 必须**限定在 trial mode**。

### 产品与文档口径

1. 默认显示 **Δ设计**（对额定），因为那是用户手上的数；**Δ实测** 作为附加信息；
2. 若用户只给额定值、又想知道"实际会跑到多少"，用上面这张梯子做显式换算（并给出区间），
   而不是让模型悄悄吸收；
3. 报告里所有百分比都必须标明目标是哪一种 —— 之前几节的数字全部是 **trial mode**。

### 测试

数据集测试增至 **15 例**：额定块的出处必填、字段缺失必须拒绝、梯子中位数必须 > 1（试航高于额定）。

## 24. design mode 落地（默认面向用户的那一套）

### 先量清楚：对额定值时模型偏多少

27 条同时带额定与试航的案例上：

| 目标 | MAPE | 中位 | 形态 |
|---|---|---|---|
| **额定值（design mode）** | **23.04 %** | 23.51 % | **全部高估**，+8 % … +50 % |
| 试航值（trial mode） | 11.19 % | 10.88 % | 有正有负 |

差别不是"精度"，是**形态**：对额定值时这是纯粹的**水平偏差**（每一条都正），
所以一个常数就能压下去；对试航值时偏差跨零，常数反而有害（第 19 轮的结论）。

### 拟合与验证

| 口径 | MAPE |
|---|---|
| 未校正（对额定） | 23.04 % |
| 全局因子 **0.8079**（样本内） | 10.20 % |
| 全局因子 0.8079（**嵌套 LOOCV**） | **10.56 %** |

即：**design mode 用一个全局因子就够**，而且 LOOCV 后 10.56 % 甚至优于 trial mode 的原始 11.19 %。

### 代码

- 场景新增 `target_mode`：`design` | `trial`（缺省仍为 `trial`，不改变既有场景）；
- `calibration: {mode: "design"}` → 施加 0.8079 的全局因子，行里带 sample / LOOCV / 出处；
- **冲突守卫**：design 模式下若声明 `mode: "cluster"`（试航拟合的船型校正），
  给阻断级 `calibration.mode_conflict`，拒绝执行 —— 那条校正会把"额定→试航"的梯子再算一遍，属双重惩罚。

### 测试

阻力/校准/混合/数据集合计 **62 例通过**（新增 3 条：design 模式全局因子、冲突守卫、缺省仍走旧行为）。

## 25. 让"偏差"必须带目标类型（第 25 节起的产品口径）

之前所有百分比都有一个隐含前提：**跟谁比**。现在把这件事变成显式接口。

场景可以声明：

```json
"target": { "kind": "design", "shp": 20000, "speed_kn": 12.0, "source": "builder contract" }
```

阶段会在**对应航速的那一行**附加：

```json
"comparison": { "kind": "design", "target_shp": 20000.0, "modelled_shaft_hp": 21180.4,
                "deviation_pct": 5.9, "source": "builder contract" }
```

四条规矩：

1. **`kind` 必填**（`design` / `trial`）—— 不写类型就不给百分比；
2. **`source` 必填** —— 目标值也是数据，要有出处；
3. **只在同航速比较**：目标航速与请求航速不一致时，该行不产生 `comparison`（测试用 10 kn 请求对 12 kn 目标验证）；
4. **不假设**：没声明 `target` 就不产生比较块，不做"默认拿谁的额定值来比"。

这样界面/报告可以直接读 `comparison.kind` 决定标题写"相对设计意图"还是"相对实测"，
不需要前端自己猜这个数的来历。

测试：阻力 + 场景校验 **43 例 + 121 subtests 通过**（新增 3 条：偏差与类型、跨航速不比较、无目标不生成）。
