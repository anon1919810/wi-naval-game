# 本轮交付：类 SPS 计算核心

2026-09-22 用户最新要求：“只需要先做完类SPS的计算功能”。本文件据此
调整当前执行阶段；它优先于原完整 Plimsoll 1.0 计划中的界面、部署与
独立打包要求。原计划保留为后续产品路线，不再作为本轮的全部完成闸门。
这项范围调整来自用户，不是因已有测试通过而自行缩减目标。

## 本轮必须完成

1. 统一输入、单位、坐标、来源、估算和未知值语义；可编辑的全船重量账本、
   正常/满载/自定义载荷和质量矩；现有项目迁移、保存与重开。
2. 将装甲、武器/炮座/弹药、动力、燃料与续航输入接到同一重量和载荷状态。
   提供可审查的物理质量修订与实际应用接口，不重复计重。
3. 完成 L0 参数化与 L1 型线静水力、载荷浮态、GM/GZ、倾斜液舱、
   Bonjean/静水力曲线及已知甲板/开口的限制判断。
4. 完成同载荷下的 Taylor-Gertler、Schoenherr、Holtrop-Mennen、功率和
   QPC 敏感性计算。估算、方法越界和历史比较条件必须显式保留。
5. 将已经开发的连通准静态破损计算、剩余 GZ、守恒、失败/取消状态验完，
   并接入统一计算入口。此项是 Plimsoll 的既定扩展，不声称 SPS 同样提供。
6. 提供通用 Python 接口和实际单工况、批量、参数扫描命令，项目 JSON、
   计算 JSON 与 CSV 导出。无需图形界面即可运行方箱、通用船、Queen Mary
   正常/满载和编辑后工况；错误与警告不能在调用链中丢失。
7. 保留七页字段逐项覆盖清单，指向实际计算输入/输出，明确估算和原批准
   范围内的排除项；不以页面数量或字段占位代替功能完成。

## 本轮验收

- 统一协调入口、项目编辑/保存/重开、实际 CLI 批量/扫描及导出走通。
- 解析/数值/外部公式基准、预先声明的容差、关键变异检查和全套核心回归通过。
- Queen Mary 与通用案例各自使用一致载荷；缺值、来源与估算贯穿结果。
- 独立代码审查中的重大计算、数据丢失和误报有效性问题已修复。
- 记录当前机器上核心单工况、批量、GZ 和进水计算的实际耗时；提供简明
  调用说明、输入/输出契约、已知限制、测试证据及本地 Git 提交。
- 保留用户主仓库和 Unity 原有成果。不得宣称已全面超越 SPS 或获得
  历史实船/工程认证。

以上通过后，报告“本轮计算核心阶段完成”。不要报告“完整网页版/应用版
Plimsoll 1.0 已完成”。此前的完成通知授权保留；正式通知前须在当前任务
明确本轮完成范围，不能把已发送的通知通路测试当作正式完成通知。
