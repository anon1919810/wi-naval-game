# 高级输入、破损研究与显示单位完成计划

用户已要求补齐六页表单交接中保留的这三类缺口。本轮沿用既有网站、项目修订、计算核心和后台工作进程，不修改游戏、资产仓库或服务器。设计边界是让现有计算能力可通过表单操作，不增加新物理模型。

## 实施顺序

1. 补齐高级表单：阻力场景的两种既有方法、输入来源、QPC/敏感性、附体和首侧推；系统的四种既有物理质量模型与炮/炮座/弹药行绑定。模型只提出质量计算结果，编辑模型不得静默改账本重量。
2. 补齐破损流程：保存场景草稿、增删与编辑舱室/海水/连接/开口、选择已保存场景、明确时长/步长与剩余稳性采样、校验并提交同修订同工况请求。沿用运行页的队列/取消/失败/报告路径。结果显示停止原因、实际推进时间、守恒误差、进水量/姿态时间序列及剩余 GZ，保留模型边界。
3. 实现项目级单位显示：长度 m/ft、质量 t/kg/long_ton、功率 kW/shp、航速 kn/m_s、角度 deg/rad。输入先换回字段规范单位，结果只在展示时换算；面积/体积/质量密度等采用明确字段单位，不从数值猜量纲。保存、计算、JSON/CSV 导出及指纹语义保持规范单位，切换显示不累积修改数值。
4. 集中验收、文档和本地提交。OpenCode 实现；Codex独立读差异、执行针对性/集中测试并做实际浏览器流程。最多两轮返回修复，之后接回。

## 数据与界面约定

- 沿用浅色/深色和现有表单组件，不增加依赖，不修改锁文件。
- 未知与零分开；所有需要来源/估算的研究保留出处与三态编辑。未完整声明可保存为草稿，但不得提交伪有效计算。
- 新保存的 `flooding_scenarios` 是研究输入，不是第二份重量账本；作轻量结构/引用校验，不在保存时执行数值计算。旧项目缺字段仍可读取。运行以现有 flooding 请求契约及内核校验为最终权威。
- 整个请求沿用工作台选择的项目修订和工况。场景/请求不允许旧结果冒充当前结果；报告附请求身份。
- 结果展示覆盖工作台、运行/报告及稳性曲线。原始 JSON 和导出明确标为规范单位；未知量纲保持原标签和规范值。
- 合成示例明确标记，不用自动填入的数值冒充 Queen Mary 史实。复制舱室进场景需显式操作，初始液体不可与基准载荷重复计重。

## 验证安排

实现期间按高级输入、破损、单位三簇集中验证；不用每改一步跑全量。验收包括：声明保存重开与其他字段保留；阻力/质量模型的数值域和来源；破损非零时长有效请求、缺值/引用错误拒绝、取消/失败显示；单位双向转换、未知/零、反复切换不漂移、旧项目默认、工作台与报告一致、原始导出不变。

最终执行前端全套与生产构建；必要的后端/新增契约针对性测试。若本轮增加核心存储契约，冻结后运行一次核心全套；仅前端修改不重复核心全套。实际浏览器用独立临时库及本地测试邮箱完成保存、重开、破损运行和报告，公网不部署。

不以测试数量证明史实或工业级可信度；不实现穿甲/爆炸/碎片求解、CFD、结构强度、SPS 专有评分或游戏实时接入。
