# Plimsoll 1.0 长期目标与完成标准

状态：供用户设置为长期目标后执行；本文件的编写不代表已启动开发目标。
设计日期：2026-09-22。

## 总目标

把现有 Plimsoll 完成为可在本机独立使用的舰船设计、载荷分析与简化破损稳性工具 1.0。
贯通“编辑舰船与重量分组 → 选择载荷 → 求平衡浮态 → 静水力/稳性/阻力分析 → 破损试验 → 比较与导出”的完整流程。
Queen Mary 是完整示范案例，核心保持通用。交付可启动的软件、源码、数据、测试证据与使用文档。
全部功能与验收完成后，按用户已授权的方式发送微信完成通知。

“完成”指本文件定义的 1.0 产品范围完成，不代表解决全部造船学问题，也不代表获得真实舰船设计认证。
算法正确性、软件可用性、史实数据可信度分别记录，不能相互冒充。

## 执行阶段与交付

### A. 建立一致的数据与项目基础

1. 盘点现有源码、案例、测试、生成器、未提交修改和已有独立界面工作；根据实际状态选择复用，避免重做。
2. 修正文档中的过时百分比、模块状态与“史实验证通过”等不成立表述，形成唯一的当前范围清单。
3. 统一长度定义（Lwl/Loa/Lpp）、公吨/长吨、密度、速度、功率单位、龙骨/水线坐标、正常/满载/自定义载荷。
4. 为输入和派生结果提供来源、估算标记、适用范围、数据版本和依赖关系。未知用空值与原因表达，显式零与未知不能混用。
5. 定义跨模块错误与警告结构；从计算核心到 CLI、报告、界面、导出的信息保持一致。
6. 给现有 schema 变更提供迁移说明或兼容读取；不能静默误读旧案例。

验收：同一设计、同一载荷的所有模块使用同一组状态数据；修改任一依赖后结果失效并重算；来源与警告不会在聚合过程中丢失。

### B. 完成全船重量与载荷体系

1. 完成船体结构、装甲、武器与炮座、机械锅炉、舾装、弹药、煤油、淡水和其他载荷的分组。
2. 每项质量及其纵向、横向、垂向重心可编辑，可标识数据来源和估算区间。
3. 明确炮座质量是否包含装甲、弹药是否包含装药等边界，防止重复计入。
4. 自动合成总质量、LCG、TCG、KG，建立正常、满载和自定义工况；消耗品变化能传递到浮态与稳性。
5. 资料不足时使用有说明的工程估算并给敏感性范围；不得填一个任意“补差重量”来伪造吻合。未分配质量应显式显示，不能自动获得虚构重心。
6. Queen Mary 完成所有重量类别的可操作输入；历史未知项允许估算，但必须显著区分“案例可运行”与“重心已由史料验证”。

验收：分组加总、单位换算、坐标换算和质量矩守恒通过独立算例；缺重要重量时禁止把部分 KG 标成全船确定值。

### C. 完成静水力与稳性分析闭环

1. 保留 L0 参数化与 L1 型线计算；完善输入校验、湿面积、船型系数、Bonjean 与静水力曲线。
2. 根据载荷总质量和重心求吃水、纵倾及必要的横倾平衡，报告残差、收敛状态和几何可承载范围。
3. 正常/满载工况分别求解，不能把模型设计水线的结果当作全部工况结果。
4. 完善 GM、自由液面、GZ、小角度一致性检查，以及甲板浸没、开口进水和有效角度限制。
5. GZ 的峰值、正稳性区间和失稳边界必须区分“实际求得”“采样截断”“超出模型适用范围”；不把最后一个正采样点冒充消失角。
6. 有限几何或缺开口数据时，显示代理模型限制，不构造虚假的高角度可靠结果。

验收：解析船体及独立数值基准通过；对选定非方箱工况进行站数和积分步长收敛检查；对有效工况要求质量/浮力和力矩平衡残差满足预先记录的尺度化容差。

### D. 完成简化破损试验功能

1. 舱室具有显式几何、位置、渗透率、连通关系、开口及进水状态；支持单舱、多舱、左右不对称进水与关闭连通口。
2. 完成“进水量 → 水体重心与自由液面 → 总质量与重心 → 破损浮态 → 剩余 GZ”的一致计算链。
3. 提供准静态时间推进：基于压头差与声明的流量系数计算进水/舱间流动，逐步重算浮态；对质量守恒、流向、舱容上限和时间步长进行验证。
4. 明确一种质量/浮力处理方法，禁止增重法与损失浮力法双计；开口和液面超过简化模型范围时发出警告或停止给出不可信结论。
5. 对非零倾角下的矩形舱液体使用一致几何处理，或对尚不支持的状态显式拒绝；不能静默沿用水平液面重心。
6. 提供状态时间线、剖面图、进水舱高亮和结果对比；无需精细可漫游舰内场景。

验收：空舱、满舱、零渗透率、关闭自由液面、左右镜像、同压无流、体积上限、连通守恒和时间步长收敛均有独立测试；失败和失稳状态可见，不能仅凭 GM 正值宣布安全。

### E. 完成武备、装甲、动力与阻力模块

1. 七个参考页的字段逐一标记“实现”“有计算但输入估算”“明确不纳入 1.0”，避免空壳页或零值占位。
2. 装甲面积/厚度/密度/质量、炮与炮座/炮塔装甲、弹药和其他武器数据能与重量体系对接，避免各页各算一份。
3. 完成动力、燃料、功率与续航的可追溯输入；缺乏耗油率时，不把输入的历史续航冒充算法预测。
4. 完善 Taylor-Gertler 速度—阻力—功率计算、适用范围检查、缺格处理、Schoenherr 口径核对、QPC 敏感性与不同载荷对比。
5. 增加 Holtrop-Mennen 独立对照方法，用有出处且满足其适用条件的基准验算；越界工况不作为主结果。任何缺少的形状输入都须显式提供或标估算。
6. 核对图谱的长度、湿面积和系数定义。试航比较必须采用相同速度，并披露载荷差异；不调参凑验收。

验收：公式与单位用独立手算/文献算例验证；无表、无有效插值或缺必要输入时不生成貌似完整的总功率；比较结论同时列出假设和适用性。

### F. 交付可直接使用的本地应用

1. 核心保持独立 Python 库；CLI 支持单工况、批量、参数扫描与导出。
2. 在 A–E 的核心接口稳定后恢复本地 Web 界面。用户启用本目标，即同意将此前搁置的界面纳入本轮，但仍以后端可用为前提。
3. 界面支持创建/打开/保存设计、重量分组编辑、载荷切换、运行计算、曲线与剖视、破损场景、比较方案及查看来源/估算/警告。
4. 提供项目 JSON、计算 JSON、CSV 和可离线阅读的 HTML 报告；导出附单位、坐标、载荷、版本、有效性与估算信息。
5. 提供独立的游戏数据导出示例和读取契约，不直接修改现有 Unity 工程。
6. 交付 Windows 启动入口、依赖安装说明和示范工程。核心计算及日常使用不依赖外网、密钥或在线 AI 服务。
7. 本地服务默认仅监听回环地址；无需部署公网或创建云服务账号。

验收：从独立发布目录按说明启动，完整操作一次“打开 Queen Mary → 改载荷 → 重算 → 查看警告和曲线 → 跑破损 → 保存 → 重开 → 导出”。不得只用接口测试替代实际界面验收。

### G. 独立验证与发布收尾

1. 保留并扩展现有测试。解析方箱、非方箱/通用测试船、Queen Mary 分别用于公式、通用性和完整案例验证。
2. 引入有可核对输入和答案的外部基准；历史值只验证其资料支持的量，未知 KG 不能用于断言真实 GM 准确。
3. 容差在对照前根据解析解、离散误差或方法依据确定，不根据当前输出反调。
4. 对关键错误开展变异验证；保存测试命令、结果、基准来源和数值残差。
5. 在当前机器测量单工况、批量、GZ 与破损时间线耗时，记录硬件、案例规模和重复测量结果；界面不能因长计算失去响应，须显示进度或可取消状态。
6. 核对可重复生成、迁移、离线运行、中文路径和错误恢复。生成物、源码和文档保持一致。
7. 提供发布目录/归档包、版本说明、用户手册、开发接口、数据字典、已知限制、覆盖清单和续接文档。
8. 建立可审查的本地 Git 提交，保留用户原有修改。远端推送、合并或发布只有在现有授权涵盖时执行，不能擅自修改仓库权限或强推。

## 最终完成闸门

只有以下条件全部满足，才能宣告 Plimsoll 1.0 开发完成：

1. A–G 的范围内交付已完成，范围内没有未实现的必需功能。
2. Queen Mary 能完整走通设计、载荷、稳性、阻力、破损、保存与导出；通用算例没有船只专属常量依赖。
3. 质量、单位、坐标、载荷、估算及警告语义一致；无未解释的双计、静默缺值补零或错误“验证通过”。
