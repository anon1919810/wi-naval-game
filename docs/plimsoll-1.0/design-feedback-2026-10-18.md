# 原生设计改动反馈与按需加载交付

2026-10-18，本地已验收候选。基于 `c59a47e`，本轮未提交、推送或部署；线上仍为此前发布的 `34ee279`。

## 使用变化

- 普通原生设计章节的工具栏新增“改动”。展开后，对照实际已保存修订和当前草稿，显示九项原生读数、声明输入变化及估算／手工指定重量策略变化，可跳转至相关章节。
- 草稿差值是“草稿 − 已保存”。保存成功后，新修订成为基线，差值归零。基线读取失败可以重试；项目、修订或文档内容变化时，旧响应不会进入新比较。
- 修改正在确认或确认失败时，保留输入、隐藏旧读数的差值，并禁止保存和运行。失败入口在所有原生章节可见，可以重试；沿用原有顺序队列，没有合并或跳过源事件。
- 两份冻结报告新增简明原生摘要，差值沿用现有完整对照表的“对照 − 当前”。摘要只读取保存的结果与输入快照，不重新计算历史运行。
- 九项读数为选取质量、来源估算质量、目标排水量、平衡差额、最大航速、来源马力、续航里程、来源经验稳性和来源船体综合强度。未知值保留未知；经验稳性不作为初稳性高，综合强度不以纵／横强度替代。
- 声明输入分别标注两侧来源单位；切换尺度后，不给两个不同单位的原始值套用同一单位。报告方法、模式、工程身份或基准工况不兼容时，停止数值相减并说明原因。
- 工作台、运行页和报告页按路由加载。页面文件加载失败时，提供明确的重新载入入口；实际失败后已证实重新请求成功，并保留工程地址和匿名工作区身份。

## 集中验收

Codex 独立审阅了实现，运行受影响前端批次。首轮失败集中在新增比较文件对原生载荷工程身份的错误假设，已修正为读取外层工程／运行身份；只重跑了受影响文件。相关批次现均通过，生产构建通过。随后两处文案／窄屏样式收尾重新构建，未重复运行无关矩阵或 Python 套件。

隔离本地数据库、真实 API 与后台 worker 完成以下闭环：

1. 从规范 JSON 备份恢复受控合成工程，冻结修订 1。
2. 修改船宽和主装甲带，注入一次修改延迟、一次请求失败，确认旧读数被隐藏、保存／运行受阻，重试后输入保留且读数恢复。
3. 把甲板装甲改为手工指定，在原估重上增加 10 t；保存修订 2，刷新后保留该重量与策略，九项草稿差值归零。
4. 实际运行修订 2，与修订 1 对照；页面九项数值和差值逐项匹配保存载荷，旧运行完整记录保持相等。
5. 切换来源 m／ft，确认两侧单位分别正确显示；切换中英与深色主题，检查 390 px 界面。表格在卡片内横向滚动，指标名称保留可读宽度，桌面四列可见。
6. 实际注入一次工作台文件 503，点击恢复后同一文件重新请求成功。

核心 `tools/plimsoll/` 与 `web/backend/` 的既有文件哈希与开工基线相同。独立源审阅未见新增核心或后端文件；没有改动依赖、登录、持久化及生产环境。
