# Plimsoll 舰船设计统一整合

目标：Plimsoll 自身完整承接原版 SpringSharp 3b3 的设计功能，再开展增强。用户不需要进入另一种 SPS 模式，也不需要在两套表单之间同步参数。

## 当前状态

本轮原生主流程已验收：在已冻结的本机 SpringSharp 3b3 主设计范围内，原参数、操作和报告由 Plimsoll 普通章节承接，使用同一份设计、共享船体投影和重量台账。普通设计不再需要切换独立 SPS 模式。增强项尚未开始。

这是对该冻结版本功能及受控输入的验收，不是实船校准或全部输入组合的逐位证明。本轮仅本地源码与构建，未提交、推送或部署。

## 已建立的数据关系

- `project.ship_design` 是唯一的舰船设计声明；旧 `sps_3b3_design` 只在旧工程升级时读取，升级草稿移除旧活跃声明，历史修订不变。
- 普通章节使用同一份参数：船体、干舷、五炮组、辅助武器、装甲、动力、性能及报告注释。沿用已经与本机原程序核对的公式与单位语义。
- `project.hull` 的共享主尺度是上述声明的 SI 投影。清除已知输入不会保留旧的已知尺寸；直接编辑造成不一致时保存拒绝。
- 自动估重写入真实重量台账。估算以设计工况为作用范围，其他工况与派生定义保留。不会补造重心。
- 人工重量需要明确绑定用途；合并计重和含义不明的旧项目先提示绑定，避免自动追加明细导致重复。重新导入源文件保留已经确认的人工质量绑定。
- 平衡同时列出所选质量、经验估重、目标排水量和差额。自动结构残差采用源程序的 H0 显示值，不使用强度计算变换后的 H1；燃料、弹药、其他载荷及炮塔装甲均只计一次。
- 基础 `ship_design` 分析不依赖型线和 CG；详细物理分析仍明确保留缺项状态。基础报告不会因旧重量待绑定而被禁止导出。

## 保存及互通

预览不会保存工程；保存沿用既有修订和并发冲突机制。报告、比较与下载读取运行时冻结的数据，不会用当前草稿重算旧报告。

原 `.sship` 文件、TXT、RTF、SSR、JSON、CSV 的读写沿用已核对的源格式。新建网页空白工程以 `ship_design` 模板建立；既有 API 的 `template=null` 和原物理模板保留原语义。

项目库的 `.sship` 入口直接建立原生设计及自动估重台账；2.0、3.0 均可读取，1.x 按本机原版规则拒绝。预览分别说明 222 个有效参数和原文件的 136/280 个位置记录，不再把旧物理迁移的占位条目当作完整设计。原始字节及其摘要存档。

原版混合单位、Single 精度及事件缓存的可达行为保留。例如同一组船宽、口径、装甲厚度编辑后，冻结的原生读数与原程序实际执行该编辑序列的读数一致；`.sship` 重新打开会按原版文件精度和加载事件重算，不能保留所有锁定和临时缓存。完整编辑状态、人工重量、绑定及工况以项目 JSON 保存；原格式报告仍报告源方法估计，人工差额另列在统一平衡中。

## 普通操作流程

1. 在项目库新建舰船设计，或导入 `.sship`。既有物理工程可在概览中显式初始化；旧兼容工程升级为待保存草稿，历史修订保留。
2. 按普通章节编辑船体、干舷、五炮组、辅助武器、装甲、动力和性能。等待修改确认后保存。
3. 重量页先看同一台账的估算、所选质量、目标与差额；绑定设置中可将某项切为人工声明并修改质量。条目位置和来源独立折叠，自动估重不会补造 CG。
4. 运行基础舰船设计即可生成冻结报告，不依赖型线或重量位置。附加物理检查在补齐依据后单独请求。
5. 报告首页读取本次保存的设计摘要，支持运行对比和原文件/文本/富文本/JSON/CSV 下载。项目 JSON 备份可恢复完整设计与人工台账。
