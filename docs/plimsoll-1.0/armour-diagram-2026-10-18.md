# 原生装甲示意图交付 · 2026-10-18

本轮已完成本地独立验收，尚未提交、推送或部署。它将原生设计已有的装甲尺寸、估重政策和重量台账连成可选择、可编辑、可导出的示意图。仍然共用普通章节中的一份 `ship_design`，没有新增独立 SPS 模式或计算方法。

## 使用效果

进入「装甲与装备」，可查看主装甲带、端部装甲带、上部装甲带、舱壁、防雷鼓包的长度比例条带，以及干舷端点背景、甲板分段、七种覆盖选择和前后司令塔厚度。尺寸缺失或无效时给出说明，已知零值保留为零。

用鼠标或键盘选择区域，可读取尺寸、估算／手工政策及采纳质量和来源估算；「编辑此区域」会打开原有字段分组并聚焦输入。相对保存修订发生变化的区域会高亮，保存后恢复基线。草稿仍在确认或确认失败时，图和导出按钮隐藏；全局失败重试保留输入。

运行页与完整报告中的示意图读取各自冻结的原生结果，带运行身份、只读显示。旧原生报告也能派生示意图，不需要重算或改写历史记录。SVG 和 PNG 下载包含全部区域、单位、政策、质量、平衡读数与说明，不随当前选区丢失其他内容。支持中文、英文和深浅主题；390 像素下在图内横向滚动，正文页面不被撑宽。

## 图的含义和边界

条带只按声明长度与水线长度的比例绘制；居中是一项示意约定。原始设计没有声明装甲带起始站、垂向安装位置、司令塔位置或真实水线轮廓，因此图不会推断这些事实。甲板表示声明分段与覆盖选项，不代表实际防护面积；机械舱、弹药库的位置未知时不放置箱体。舱壁保留原方法的附加／加强类型语义。

尺寸读取原生规范化的英尺／英寸结果，再做显示转换。所有质量只读取既有台账及平衡；装甲块中的 long tons 字段不被当成公吨使用。前后司令塔共用的角色质量只显示一次。本轮没有增加重量公式、装甲效能评分、自动布置、CG 推断或实船校准。

## 独立验收

Codex 完成源码审阅后，对 8 个相关前端测试文件做了一次集中验收，91 项通过。真实图片下载暴露了独立 XML 属性格式问题，另补一项 XML 解析回归；修正及图片排版收尾后，仅重跑导出所在文件的 29 项，全部通过。最终生产构建通过，保留既有 Scene 大包告警；未重跑未修改的 Python／后端全量矩阵。

本地真实浏览器、API、SQLite 和计算 worker 使用受控合成工程完成了以下流程：

- 主装甲带由 6 改为 7 英寸，图与台账同步；七秒延迟及一次 503 失败期间不展示旧数值，重试保留输入并正确高亮。
- 甲板以来源估算加 10 吨的手工质量采纳，图保留来源尺寸及独立估算质量。保存到修订 2、重载后政策与数值保留，高亮复位。
- 修订 2 实际计算完成；后续工程保存到修订 3、主带改为 8 英寸，修订 2 报告仍为 7 英寸，原修订 1 运行仍为 6 英寸。两个冻结记录均逐字段保持一致。
- 中英文 SVG／PNG 均由实际下载按钮落盘；SVG 按 XML 解析，七个角色、运行身份和质量齐全。PNG 分别为 1600×2607、1600×2373，已查看实际图片并核对非空像素及排版。
- 390 像素下，报告图画布为 262 像素、内部图宽 900；工作台画布为 306、内部图宽 900。页面宽度均为 375，无图中文字越出 SVG 边界。

计算核心和后端文件摘要与起始快照一致；上一轮已验收、未提交成果除指定集成点外保留。项目库静态 JavaScript 闭包仍为 693,094 字节，gzip 203,504 字节，按需加载收益保留。这是字节测量，不是加载时延基准。
