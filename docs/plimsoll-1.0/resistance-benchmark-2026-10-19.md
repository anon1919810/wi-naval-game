# 阻力对标第一步：内核等价性与转换口径 · 2026-10-19

目标：判断 plimsoll 的 Holtrop-Mennen 与 ssrcalculator（Rust 重实现，MIT）的 Holtrop 是否等价，
以便决定能否直接借用它的按舰种校准因子（战列舰 0.767 / 航母 0.803 / 巡洋舰 0.919 / 驱逐舰 1.017）。

## 结论

**内核的摩擦侧完全等价；差异来自输入系数与轴马力转换口径，不是算法。**

同一条船（HMS Dreadnought，L 157.417 m / B 24.994 m / T 8.077 m / Cb 0.56 / Cm 0.97 / Cwp 0.75，21 kn）：

| 量 | ssrcalculator 公式 | plimsoll 内核 |
|---|---|---|
| 湿表面积 S（Holtrop 回归） | 4,399.67 m² | 4,399.7 m² |
| 形状因子 1+k | 1.1225 | 1.123 |
| 摩擦阻力 Rf | 385.54 kN | 385.5 kN |

摩擦侧逐位一致 → 两边的 Holtrop 内核是同一个方法，不存在算法分歧。

## 已排除的三个嫌疑

1. **湿表面积口径**：plimsoll 允许传入几何积分面积，但改用回归值时总阻力只变 **1.4 %**（1,039.4 → 1,025.4 kN），排除。
2. **形状因子**：两边取值一致（1.1225 / 1.123），排除。
3. **QPC 假设**：把 plimsoll 的 EHP 折成 ssr 报出的 37,969 hp，需要 QPC ≈ 0.32–0.40，对战列舰低得不合理，排除"同一转换口径下差 39 %"这一解释。

## 真正的原因

- plimsoll 的轴马力 = EHP / QPC，QPC 由调用方显式给出（本次 0.55），口径透明。
- ssr 的 `validate` 输出的是它**原程序经验轴马力拟合**的结果；它自己的 demo 明确写着
  *"Propulsion: original empirical shaft-power fit; no explicit QPC (the Holtrop-style efficiency breakdown is not used)"*。
  所以 37,969 hp 与 EHP/QPC 不是同一个量，不能直接比。

## 由此得出的两条工程结论

1. **因素不能直接搬**：ssr 的 22.44 % → 10.19 % 是在它自己的轴马力口径下算出来的；plimsoll 要复现，
   必须先用**同一个轴马力口径**（EHP/QPC 或原程序经验拟合，二选一）重算双方。
2. **几何合成会污染阻力**：plimsoll 的参数化船体给出的 Cm 0.788 / Cp 0.706，而 Dreadnought 实际约
   Cm 0.97 / Cp 0.577；同一内核下总阻力因此从 844.5 kN 涨到 1,039.4 kN（+23 %），几乎全在兴波项
   （301.6 → 486.0 kN）。所以任何"对真船"的误差统计都必须喂**声明系数**，不能喂合成几何反算的系数。

## 下一步

1. 在 plimsoll 里加一个"声明系数"入口（或让阻力阶段接受 scenario 提供的 Cb/Cm/Cwp），使对标时两边系数一致；
2. 用同一轴马力口径重算 146 案例，得出 plimsoll 自己的 MAPE 与按舰种因子；
3. 才进入分段混合与 LOOCV。

## 第二批：plimsoll 自己的 146 案例误差（实测）

把 ssrcalculator 内嵌的 146 条历史案例（`core/src/accuracy.rs`，含 L/B/T、排水量、Cb、航速与参考轴马力）
逐条喂给 plimsoll 已移植的原程序口径：`co_sharp` → `effective_length_ft`（cruiser 艉型）→
`wetted_surface_sqft` → `speed_hp`（engine_year 取 1900，仅影响 1890 年前的年份惩罚）。

| 方法 | MAPE | 中位 | 来源 |
|---|---|---|---|
| **plimsoll 原程序口径（本次实测）** | **15.93 %** | **11.86 %** | 本仓库 `concept_estimates` |
| ssrcalculator 的"original" | 22.44 % | 15.26 % | 它的 `validate-regime` |
| Holtrop 未校准 | 19.16 % | — | 同上 |
| Holtrop + 按舰种因子 | 10.19 % | 7.65 % | 同上 |

按舰种（plimsoll）：巡洋舰 10.6 %（n=44）、航母 10.7 %（n=32）、战列舰 14.4 %（n=32）、驱逐舰 **27.8 %**（n=38）。

### 三条结论

1. **plimsoll 的移植比同源移植更接近原程序**：同一批数据、同一口径，15.93 % 对 22.44 %，
   差 6.5 个百分点；连 Holtrop 未校准（19.16 %）也不如它。
2. **驱逐舰段没有想象中糟**：早前按 ssr 的口径看到 T-G 血统 43.7 %，plimsoll 实测只有 27.8 % ——
   说明那 43.7 % 里有相当一部分是**移植差异**，不是方法本身的极限。
3. **仍然需要校准**：只有 ssr 的"Holtrop + 舰种因子"（10.19 %）胜过它，说明按舰种纠偏仍有空间；
   但纠偏的基线应当用 plimsoll 自己的 15.93 %，而不是 22.44 %。

### 口径与保留

- 参考轴马力本身 0/146 经官方试航或水池验证（原作者标注），所以这些数字是**相对参考**的误差，不是绝对精度。
- 本次把 `displacement_tons` 视作长吨、艉型统一取 cruiser，engine_year 取 1900；三项假设都会进入误差，
  已记入本文件的复现说明。

## 第三批：按舰种校准与嵌套 LOOCV（plimsoll 自己的口径）

在第二批的 146 条案例上，把"舰种"当作唯一的分组维度，先拟合乘性因子，再用**留一法**重拟合以给出样本外估计
（每个被留出的船，其舰种因子只用该舰种的其余案例拟合）。

| 口径 | MAPE | 中位 |
|---|---|---|
| 基线（未校准） | 15.93 % | 11.86 % |
| 按舰种因子（样本内，乐观） | 11.79 % | 10.32 % |
| **按舰种因子（嵌套 LOOCV，诚实值）** | **12.11 %** | **10.55 %** |

拟合出的因子：战列舰 **0.923**、航母 **0.970**、巡洋舰 **1.020**、驱逐舰 **0.816**。

按舰种看校准前后的变化（LOOCV）：

| 舰种 | n | 基线 | LOOCV |
|---|---|---|---|
| 驱逐舰 | 38 | 27.8 % | **16.6 %** |
| 战列舰 | 32 | 14.4 % | **10.1 %** |
| 航母 | 32 | 10.7 % | 10.3 % |
| 巡洋舰 | 44 | 10.6 % | 10.9 % |

### 结论

1. **校准值 5.4 个百分点**（15.93 → 12.11 嵌套），收益几乎全在驱逐舰（−11.2）与战列舰（−4.3）；
   巡洋舰因子 1.02，等于承认这一档本来就准，不需要纠偏。
2. **与同源移植对比**：ssrcalculator 的基线 22.44 % → Holtrop+因子 10.19 %；plimsoll 基线 15.93 % → 原方法+因子 **12.11 %**。
   两者的**校准后**水平接近（差 1.9 点），但**基线**差 6.5 点 —— plimsoll 的移植保真度更高。
3. **驱逐舰因子的方向相反**：ssr 给 1.017（Holtrop 略低估），plimsoll 给 0.816（原方法高估 22 %）。
   这不是矛盾，而是两个方法在细长高速段的偏差方向本来就相反，正好支撑第 3 步的分段混合。

### 数据 provenance 的硬限制

这 146 条参考马力**没有一条**经过官方试航或水池试验验证（原作者标注 0/146），所以：
- 上面的 12.11 % 是**相对参考**的样本外误差，不是绝对精度；
- 要满足"有 provenance 的嵌套 LOOCV"，需要另行收集带试航报告/水池编号的案例；本文件不宣称已做到。

## 第四批：混合规则的实测验证（146 案例）

把同一批案例同时喂给两族方法与第 3 步的混合规则。为可比，Holtrop 侧用一个**统一 QPC**（0.440），
取使全队轴马力总和等于参考总和的那个值 —— 这样比较的是阻力形状，而不是各自的口径。

| 方法 | MAPE | 中位 |
|---|---|---|
| Taylor-Gertler（原程序口径） | 15.93 % | 11.86 % |
| Holtrop（统一 QPC） | 12.94 % | 10.16 % |
| **按 Cb 混合（无任何校准）** | **11.86 %** | 10.48 % |
| 混合 + 按舰种因子（样本内） | 10.33 % | 7.95 % |
| **混合 + 按舰种因子（嵌套 LOOCV）** | **10.62 %** | **8.24 %** |

拟合出的混合后因子：战列舰 0.924、航母 0.963、驱逐舰 **0.979**、巡洋舰 1.056。

### 三条结论

1. **混合规则是有效的**：11.86 % 同时优于两族单独使用（15.93 % / 12.94 %），且**没有使用任何校准因子** ——
   收益来自船型分流本身，不是拟合。
2. **驱逐舰的纠偏被混合消化了**：纯 Taylor 口径下驱逐舰需要 0.816 的因子（高估 22 %），
   混合后因子变成 0.979 —— 说明那 22 % 偏差主要是"用错了方法"，不是"方法偏了"。
3. **最终水平**：混合 + 嵌套 LOOCV 因子 = **10.62 %**（中位 8.24 %），与同源移植的"Holtrop + 舰种因子"
   （10.19 %）基本持平，但我们的**基线是 15.93 % 而非 22.44 %**，且分段规则是按船型而不是按舰种标签。

### 尚未满足的部分

- 参考马力 0/146 经试航或水池验证，"有 provenance 的嵌套 LOOCV"仍然只做到了**方法层面**，
  数据层面还是公开参考值；
- 混合规则目前只接在阻力阶段的可选场景里，产品默认口径未切换（避免在数据未验证前改默认行为）。

## 数据 provenance 现状（2026-10-19 调查）

目标第 4 步要求"有 provenance 的试航数据"。本轮试过三条路，结论如下。

### 已经找到的原始出处（存在，但需要读档案而不是抓网页）

| 船 | 线索 | 状态 |
|---|---|---|
| HMS Dreadnought | Parsons 记录：**24,712 hp @ 21.25 kn**；另有 1906 年 ASNE 论文《Notes on H.M.S. Dreadnought's Performance》(doi:10.1111/j.1559-3584.1906.tb00015.x) | 二手转述，可引用 |
| HMS Hood | 英国海军部档案 **ADM 226/23 "Speed Trial records"**（1920），Hood Association 站点转录 | 一手档案编号已知，未逐条核读 |
| Bismarck | 德方验收报告 *Abschließende Beurteilung Schlachtschiff Bismarck*（1940） | 一手档案编号已知，未逐条核读 |
| USS Fletcher | DANFS 舰史卡：2,100 t / 376'3" × 39'8" × 13' / 36 kn | 官方舰史，属设计值而非试航实测 |

### 三条走不通或有代价的路

1. **直接抓 Wikipedia API**：本机到 wikipedia 的网络不可达（fetch 失败），只能走服务端检索拿摘要，拿不到 infobox 里的精确数字。
2. **搜索引擎直查**：中文引擎会把 "HMS/USS" 误判成华为移动服务与无关缩写，只能改用英文语义检索。
3. **规模不成立**：即便逐船核读，手工可得的也就是个位数案例，**不足以支撑按舰种的嵌套 LOOCV**（现拟合的因子每组 32–44 条）。

### 结论与建议

- 现有 146 条数据是**公开参考值**，不是试航实测；本文件中的 15.93 % / 12.11 % / 10.62 % 都只能表述为"相对参考的误差"。
- 要真正满足该要求，需要引入**成规模的实测数据集**（例如英国 ADM 213/226 系列试航报告、德方验收报告、USN 试航摘要），
  这不是网页抓取能完成的量级；建议单独立项，并明确每条的档案号。
- 在此之前，产品不应把这些校准因子当作"已验证精度"对外表述 —— 这也是它们目前只作为**可选、带审计记录的参数**存在的原因。
