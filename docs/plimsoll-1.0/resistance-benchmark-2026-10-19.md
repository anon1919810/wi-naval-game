# 阻力对标第一步：内核等价性与转换口径 · 2026-10-19

目标：判断 plimsoll 的 Holtrop-Mennen 与 ssrcalculator（Rust 重实现，MIT）的 Holtrop 是否等价，
以便决定能否直接借用它的按舰种校准因子（战列舰 0.767 / 航母 0.803 / 巡洋舰 0.919 / 驱逐舰 1.017）。

## 结论

**内核的摩擦侧完全等价；差异来自输入系数与轴马力转换口径，不是算法。**

同一条船（HMS Dreadnought，L 157.417 m / B 24.994 m / T 8.077 m / Cb 0.56 / Cm 0.97 / Cwp 0.75，21 kn）：

| 量 | ssrcalculator 公式 | plimsoll 内核 |
|---|---|---|
| 湿表面积 S（Holtrop 回归） | 4,399.67 m² | 4,399.7 m² |
| 形状因子 1+k | 1.1225 | 1.123 |
| 摩擦阻力 Rf | 385.54 kN | 385.5 kN |

摩擦侧逐位一致 → 两边的 Holtrop 内核是同一个方法，不存在算法分歧。

## 已排除的三个嫌疑

1. **湿表面积口径**：plimsoll 允许传入几何积分面积，但改用回归值时总阻力只变 **1.4 %**（1,039.4 → 1,025.4 kN），排除。
2. **形状因子**：两边取值一致（1.1225 / 1.123），排除。
3. **QPC 假设**：把 plimsoll 的 EHP 折成 ssr 报出的 37,969 hp，需要 QPC ≈ 0.32–0.40，对战列舰低得不合理，排除"同一转换口径下差 39 %"这一解释。

## 真正的原因

- plimsoll 的轴马力 = EHP / QPC，QPC 由调用方显式给出（本次 0.55），口径透明。
- ssr 的 `validate` 输出的是它**原程序经验轴马力拟合**的结果；它自己的 demo 明确写着
  *"Propulsion: original empirical shaft-power fit; no explicit QPC (the Holtrop-style efficiency breakdown is not used)"*。
  所以 37,969 hp 与 EHP/QPC 不是同一个量，不能直接比。

## 由此得出的两条工程结论

1. **因素不能直接搬**：ssr 的 22.44 % → 10.19 % 是在它自己的轴马力口径下算出来的；plimsoll 要复现，
   必须先用**同一个轴马力口径**（EHP/QPC 或原程序经验拟合，二选一）重算双方。
2. **几何合成会污染阻力**：plimsoll 的参数化船体给出的 Cm 0.788 / Cp 0.706，而 Dreadnought 实际约
   Cm 0.97 / Cp 0.577；同一内核下总阻力因此从 844.5 kN 涨到 1,039.4 kN（+23 %），几乎全在兴波项
   （301.6 → 486.0 kN）。所以任何"对真船"的误差统计都必须喂**声明系数**，不能喂合成几何反算的系数。

## 下一步

1. 在 plimsoll 里加一个"声明系数"入口（或让阻力阶段接受 scenario 提供的 Cb/Cm/Cwp），使对标时两边系数一致；
2. 用同一轴马力口径重算 146 案例，得出 plimsoll 自己的 MAPE 与按舰种因子；
3. 才进入分段混合与 LOOCV。

## 第二批：plimsoll 自己的 146 案例误差（实测）

把 ssrcalculator 内嵌的 146 条历史案例（`core/src/accuracy.rs`，含 L/B/T、排水量、Cb、航速与参考轴马力）
逐条喂给 plimsoll 已移植的原程序口径：`co_sharp` → `effective_length_ft`（cruiser 艉型）→
`wetted_surface_sqft` → `speed_hp`（engine_year 取 1900，仅影响 1890 年前的年份惩罚）。

| 方法 | MAPE | 中位 | 来源 |
|---|---|---|---|
| **plimsoll 原程序口径（本次实测）** | **15.93 %** | **11.86 %** | 本仓库 `concept_estimates` |
| ssrcalculator 的"original" | 22.44 % | 15.26 % | 它的 `validate-regime` |
| Holtrop 未校准 | 19.16 % | — | 同上 |
| Holtrop + 按舰种因子 | 10.19 % | 7.65 % | 同上 |

按舰种（plimsoll）：巡洋舰 10.6 %（n=44）、航母 10.7 %（n=32）、战列舰 14.4 %（n=32）、驱逐舰 **27.8 %**（n=38）。

### 三条结论

1. **plimsoll 的移植比同源移植更接近原程序**：同一批数据、同一口径，15.93 % 对 22.44 %，
   差 6.5 个百分点；连 Holtrop 未校准（19.16 %）也不如它。
2. **驱逐舰段没有想象中糟**：早前按 ssr 的口径看到 T-G 血统 43.7 %，plimsoll 实测只有 27.8 % ——
   说明那 43.7 % 里有相当一部分是**移植差异**，不是方法本身的极限。
3. **仍然需要校准**：只有 ssr 的"Holtrop + 舰种因子"（10.19 %）胜过它，说明按舰种纠偏仍有空间；
   但纠偏的基线应当用 plimsoll 自己的 15.93 %，而不是 22.44 %。

### 口径与保留

- 参考轴马力本身 0/146 经官方试航或水池验证（原作者标注），所以这些数字是**相对参考**的误差，不是绝对精度。
- 本次把 `displacement_tons` 视作长吨、艉型统一取 cruiser，engine_year 取 1900；三项假设都会进入误差，
  已记入本文件的复现说明。

## 第三批：按舰种校准与嵌套 LOOCV（plimsoll 自己的口径）

在第二批的 146 条案例上，把"舰种"当作唯一的分组维度，先拟合乘性因子，再用**留一法**重拟合以给出样本外估计
（每个被留出的船，其舰种因子只用该舰种的其余案例拟合）。

| 口径 | MAPE | 中位 |
|---|---|---|
| 基线（未校准） | 15.93 % | 11.86 % |
| 按舰种因子（样本内，乐观） | 11.79 % | 10.32 % |
| **按舰种因子（嵌套 LOOCV，诚实值）** | **12.11 %** | **10.55 %** |

拟合出的因子：战列舰 **0.923**、航母 **0.970**、巡洋舰 **1.020**、驱逐舰 **0.816**。

按舰种看校准前后的变化（LOOCV）：

| 舰种 | n | 基线 | LOOCV |
|---|---|---|---|
| 驱逐舰 | 38 | 27.8 % | **16.6 %** |
| 战列舰 | 32 | 14.4 % | **10.1 %** |
| 航母 | 32 | 10.7 % | 10.3 % |
| 巡洋舰 | 44 | 10.6 % | 10.9 % |

### 结论

1. **校准值 5.4 个百分点**（15.93 → 12.11 嵌套），收益几乎全在驱逐舰（−11.2）与战列舰（−4.3）；
   巡洋舰因子 1.02，等于承认这一档本来就准，不需要纠偏。
2. **与同源移植对比**：ssrcalculator 的基线 22.44 % → Holtrop+因子 10.19 %；plimsoll 基线 15.93 % → 原方法+因子 **12.11 %**。
   两者的**校准后**水平接近（差 1.9 点），但**基线**差 6.5 点 —— plimsoll 的移植保真度更高。
3. **驱逐舰因子的方向相反**：ssr 给 1.017（Holtrop 略低估），plimsoll 给 0.816（原方法高估 22 %）。
   这不是矛盾，而是两个方法在细长高速段的偏差方向本来就相反，正好支撑第 3 步的分段混合。

### 数据 provenance 的硬限制

这 146 条参考马力**没有一条**经过官方试航或水池试验验证（原作者标注 0/146），所以：
- 上面的 12.11 % 是**相对参考**的样本外误差，不是绝对精度；
- 要满足"有 provenance 的嵌套 LOOCV"，需要另行收集带试航报告/水池编号的案例；本文件不宣称已做到。

## 第四批：混合规则的实测验证（146 案例）

把同一批案例同时喂给两族方法与第 3 步的混合规则。为可比，Holtrop 侧用一个**统一 QPC**（0.440），
取使全队轴马力总和等于参考总和的那个值 —— 这样比较的是阻力形状，而不是各自的口径。

| 方法 | MAPE | 中位 |
|---|---|---|
| Taylor-Gertler（原程序口径） | 15.93 % | 11.86 % |
| Holtrop（统一 QPC） | 12.94 % | 10.16 % |
| **按 Cb 混合（无任何校准）** | **11.86 %** | 10.48 % |
| 混合 + 按舰种因子（样本内） | 10.33 % | 7.95 % |
| **混合 + 按舰种因子（嵌套 LOOCV）** | **10.62 %** | **8.24 %** |

拟合出的混合后因子：战列舰 0.924、航母 0.963、驱逐舰 **0.979**、巡洋舰 1.056。

### 三条结论

1. **混合规则是有效的**：11.86 % 同时优于两族单独使用（15.93 % / 12.94 %），且**没有使用任何校准因子** ——
   收益来自船型分流本身，不是拟合。
2. **驱逐舰的纠偏被混合消化了**：纯 Taylor 口径下驱逐舰需要 0.816 的因子（高估 22 %），
   混合后因子变成 0.979 —— 说明那 22 % 偏差主要是"用错了方法"，不是"方法偏了"。
3. **最终水平**：混合 + 嵌套 LOOCV 因子 = **10.62 %**（中位 8.24 %），与同源移植的"Holtrop + 舰种因子"
   （10.19 %）基本持平，但我们的**基线是 15.93 % 而非 22.44 %**，且分段规则是按船型而不是按舰种标签。

### 尚未满足的部分

- 参考马力 0/146 经试航或水池验证，"有 provenance 的嵌套 LOOCV"仍然只做到了**方法层面**，
  数据层面还是公开参考值；
- 混合规则目前只接在阻力阶段的可选场景里，产品默认口径未切换（避免在数据未验证前改默认行为）。

| Bismarck | 德方验收报告 *Abschließende Beurteilung Schlachtschiff Bismarck*（1940） | 一手档案编号已知，未逐条核读 |

### 三条走不通或有代价的路

1. **直接抓 Wikipedia API**：本机到 wikipedia 的网络不可达（fetch 失败），只能走服务端检索拿摘要，拿不到 infobox 里的精确数字。
2. **搜索引擎直查**：中文引擎会把 "HMS/USS" 误判成华为移动服务与无关缩写，只能改用英文语义检索。
3. **规模不成立**：即便逐船核读，手工可得的也就是个位数案例，**不足以支撑按舰种的嵌套 LOOCV**（现拟合的因子每组 32–44 条）。

### 结论与建议

- 现有 146 条数据是**公开参考值**，不是试航实测；本文件中的 15.93 % / 12.11 % / 10.62 % 都只能表述为"相对参考的误差"。

  这不是网页抓取能完成的量级；建议单独立项，并明确每条的档案号。
- 在此之前，产品不应把这些校准因子当作"已验证精度"对外表述 —— 这也是它们目前只作为**可选、带审计记录的参数**存在的原因。

## 第五批：把分流判据从一维扩到多维（含拟合结果）

在第 3 步的规则上，用同样的 146 案例与同一条嵌套留一法，试了一个线性船型分数的粗网格搜索：
`z = a1·(Cb−0.50)·20 + a2·(L/∇⅓−6)·2 + a3·(B/T−3.0) + c0`，`share = 1/(1+e^(−z))`。

| 判据 | 样本内 | **嵌套 LOOCV** |
|---|---|---|
| 现行规则（只看 Cb） | — | **11.86 %** |
| 拟合的多维分数 | 11.51 % | **11.51 %** |

最优系数为 `(a1, a2, a3, c0) = (−1, 0, −1, 1)`，也就是说：

- **Cb 仍然承担主要信息**（系数 −1）；
- **B/T 有贡献**（系数 −1：船越宽胖越偏 Taylor-Gertler）；
- **L/∇⅓ 的权重被拟合成 0**，在这个样本上没有可测贡献；
- **Fr 没有进入候选**：分流应当反映"这是什么船"，而不是"这一刻跑多快"。把 Fr 放进去会让同一条船沿功率曲线改变方法比例，
  即使数学上连续，模型性格也随之漂移，因此本文件不支持这么做。

### 结论：多维只值 0.35 个百分点

11.51 % 对 11.86 %，差距小于单条案例的噪声量级。因此：

- 拟合版以 **可选函数** `holtrop_share_form(block_coeff, beam_draft_ratio)` 的形式提供，带完整系数与出处注释；
- **默认仍是 Cb 单参数规则** —— 它的方向与按舰种的胜负一致（战列舰 24/27 偏 Taylor），
  而拟合版为了 0.35 个点会把主力舰拉到接近 50/50，反而与分类证据相左。多一个维度的代价不值得。

## 第六批：因子的稳定性（跨年代拆分）

校准因子是否只是把样本内的噪声拟合掉了？把 145 条带年份的案例按年代切一半，各自拟合、互相交叉看。

| 切分点 | 早期 n | 早期因子 | 晚期 n | 晚期因子 | 全体 |
|---|---|---|---|---|---|
| <1925 / ≥1925 | 26 | 0.913 | 119 | 0.951 | 0.946 |
| <1930 / ≥1930 | 43 | 0.931 | 102 | 0.952 | 0.946 |
| <1935 / ≥1935 | 59 | 0.950 | 86 | 0.944 | 0.946 |

**总体因子在三个切分点上稳定在 0.913–0.952 之间**，跨年代漂移不到 5 个百分点 —— 说明它抓到的是一条持续存在的系统偏差，
不是某几年的偶然。

按舰种各切一半（按年份中位切）：

| 舰种 | 早期因子 | 晚期因子 | 漂移 |
|---|---|---|---|
| 战列舰 | 0.894 | 0.935 | 5 % |
| 航母 | 0.959 | 0.986 | 3 % |
| 巡洋舰 | 1.007 | 1.032 | 3 % |
| **驱逐舰** | **0.875** | **0.763** | **13 %** |

### 两条结论

1. **主力舰的因子是稳的**（3–5 % 漂移），可以放心作为产品参数；
2. **驱逐舰的因子最不稳**（13 % 漂移），而它恰好也是混合规则抢救最多的那一档 —— 这提示驱逐舰段不应只靠一个常数因子，
   应交给第 3 步的分段混合（混合后该段因子从 0.816 落到 0.979，等于把偏差还原成"方法选择"问题）。

另有一个附带观察：**早期舰（<1925）拟合得更好**（自因子下 8.3 %，晚期 15.2 %）。原始经验法成型于那个年代，
对后来的高干舷、大功率舰反而更吃力 —— 这与"方法有时代性"的常识一致。

## 更正：站距支撑长度的接受被撤回（2026-10-19 第 6 轮）

第 1 步曾允许「场景的 FP/AP 等于站距支撑长度（而非当前水线长）」通过检查，并给出
`analysis.perpendiculars_follow_station_support` 诊断。**这条改动被撤回**。

理由来自全量核心套件的实测：`test_analysis_cases.py` 明确要求 `queen_mary_1913` 的
`holtrop-trim-study` 在两种工况下都必须 `unavailable` —— 该项目的约定是「每个工况各自存一份按水线长写好的场景，
计算不得替调用方猜长度」。接受站距支撑，等于在调用方没有声明的地方替它做决定。

于是恢复原来的严格纪律：

- FP/AP 与所选水线长必须相等（1e-10 相对容差）；
- 不符时给出具名拒绝，调用方应改用该工况自己的场景；
- 混合路径补上同一道纪律：`holtrop_inputs` 的垂线间距不符时，`blend.perpendiculars_mismatch` 阻断级拒绝，
  不再「悄悄换长度」。

**保留的部分**：第 1 步的另一半 —— 内核丢弃的航速必须补成具名缺口行 —— 与长度纪律无关，继续有效。

## 第七批：与试航记录直接对照（2 条，带出处）

第 4 步要求"有 provenance 的试航数据"。本轮至少做到了**两条**，并因此发现一个更要紧的问题。

| 舰 | 数据集里的参考 | 试航记录 | plimsoll 在试航航速下 | 对试航的偏差 |
|---|---|---|---|---|
| HMS Dreadnought | 21.0 kn / 23,000 hp | **21.6 kn / 27,018 shp**（1906-10-09 试航） | 21.6 kn → 29,700 hp | **+9.9 %** |
| HMS Hood | 32.0 kn / 144,000 hp | **32.07 kn / 超过 150,000 shp**（1920 试航，下界） | 32.07 kn → 188,762 hp | **+25.8 %** |

Dreadnought 的试航值来自维基百科转录的官方试航记录；Hood 的数字是"超过 150,000"，因此 25.8 % 只是**误差下界**。

### 由此发现：数据集的"参考值"混用了设计值与试航值

- Dreadnought：数据集用 **23,000 hp @ 21.0 kn**（设计额定），试航是 **27,018 shp @ 21.6 kn**。
  同一套模型对设计值偏 **+13.6 %**、对试航值偏 **+9.9 %** —— 差 3.7 个百分点，全来自目标值的口径。
- Hood 反过来：对设计值偏约 +31 %，对试航下界偏 +25.8 %。

也就是说，第二、三批里那些 15.93 % / 12.11 % / 10.62 % **不是对真实试航的误差**，
而是**对一个混合了口径的参考集的误差**。这既解释了为什么不同来源的复现数字差得那么多，
也说明继续在它上面精调因子是**在拟合一个不干净的目标**。

### 建议

1. 校准因子暂不作为"已验证精度"对外表述（现状即如此）；
2. 若要继续这条线，第一步是**先把目标值统一到试航实测**（至少先把数据集里误用设计值的条目标出来），
   再谈拟合；否则调得越精细，越是在拟合口径噪声。


### 更新：Hood 的试航值从下界换成实测

推进后取到更精确的记录：**1920 年全功率试航，排水量 42,200 t，151,280 shp 对应 32.07 kn**；
另有一次三小时全功率试航平均 **150,473 shp / 31.79 kn**。此前用的"超过 150,000 shp"是下界，
现替换为 151,280 shp，Hood 的偏差由 **≥ +25.8 %** 修正为 **+24.73 %**（误差不再只是下界）。

同时也说明一条方法论：**会话内的检索通道（research / 语义检索）能拿到带出处的试航数字**，
此前"抓不到 Wikipedia 所以拿不到数据"的结论只对**脚本直连**成立，对检索通道不成立。


### 新增第三条试航案例：Bismarck

出处（本次实抓，VPN 后可访问）：kbismarck.com 的测试期记录 ——
「动力装置原设计 138,000 hp / 29 kn，实测得到 **150,170 hp / 30.1 kn**」。

| 目标取法 | plimsoll | 偏差 |
|---|---|---|
| 数据集参考（**设计值** 138,000 hp @ 30.0 kn） | 157,630 hp | **+14.22 %** |
| 试航实测（150,170 hp @ 30.1 kn） | 159,708 hp | **+6.35 %** |

口径差 **7.9 个百分点** —— 比 Dreadnought 的 3.7 点更大，因为它的参考值把**设计功率**和**介于设计/试航之间的航速**配在一起。

三条试航对照汇总（plimsoll 对实测）：Dreadnought **+9.93 %**、Bismarck **+6.35 %**、Hood **+24.73 %**。
Hood 是明显的离群点，值得单独查（战列巡洋舰、32 kn、Cb 0.56 的细长高速段）。

## 第八批：四条修正一次做完（2026-10-21）

按"试航值只从正文取 / 合理性闸门 / LBP 优先 / 扩到可用规模"四条重做抓取管线，产物是
`cases/trial-cases-2026-10-21.json`（SI 存值，逐条带出处与长度基准）。

### 1. 只认"句子里自称试航"的数字

设计额定值与试航值在同一段里挨着出现（"designed for 144,000 shp … during trials provided 151,280 shp"），
所以闸门改为**读数字前面的分句**：前 170 字符里出现 trial/measured/actually obtained 才接受，
出现 design/intended/rated 且同一分句没有试航词则拒绝。

结果：36 个条目里自动通过 **3 条**（Hood 151,280@32.07、Repulse 118,913@31.73、Renown 126,000@32.58），
其余标为"仅设计值"并**排除出计分**。精确率上去了，召回率很低 —— 这正是这批数据的老问题。

### 2. 合理性闸门

航速 15–40 kn、shp/排水量 0.5–40 之外一律丢弃。此前 Invincible 抽到 "41,000 shp @ 10 kn"（误差 −95 %）
就是缺这道闸门的后果。

### 3. LBP 优先 —— 这一条影响最大

| 舰 | 用 LOA 的误差 | 用 LBP 的误差 |
|---|---|---|
| HMS Hood | +24.73 % | **+35.27 %** |

**十个百分点纯粹来自长度基准。** 阻力的参考长度本就该是垂线间长，用全长会把船放大。故文件里逐条记录 `length_basis`。
