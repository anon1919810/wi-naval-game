# Plimsoll 类 SPS 计算核心交接（2026-09-23）

本轮只交付 Python 计算核心、项目读写、CLI 和 JSON/CSV 结果。网页、服务器、
Windows 安装包及 Unity 接入尚未实施。计算结果可用于设计研究，但不能写成
Queen Mary 的史实稳性认证，也不能宣称全面复现或超越 SPS。

## 工作位置

- 分支：`feature/plimsoll-1.0`，独立工作树 `work/plimsoll-1.0`。
- 公开入口：`tools/plimsoll/analysis.py` 的 `compute_project(project, condition_id, options=...)`；
  CLI 为 `PYTHONPATH=tools python -m plimsoll`。
- 标准项目：`tools/plimsoll/cases/projects/`；源数据变化后运行
  `PYTHONPATH=tools python -B tools/plimsoll/tools/gen_project_cases.py`。
- API、CLI、行投影契约分别见 `analysis-api.md`、`cli.md`、`page-rows-contract.md`。

## 本轮新增与修正

1. 主/副炮的炮、炮座、弹药行改用**当前所选载荷账本**；炮座的旋转装甲边界
   随模型回显。单舷齐射弹重按有来源的单发弹丸质量乘单舷炮数计算，
   与全舰弹药携带量分开。鱼雷、水雷、深弹支持重复类型化声明；无账本绑定
   的质量为 `null`。Queen Mary 的五个杂项位置分区仍缺可靠质量分配。
2. 装甲行保留已声明厚度、跨度、类型字段并按非重叠账本条目分组求小计。
   最小主带长度另设“完整关键舱室范围＋艏艉余量”工程研究；
   它不是 SPS 原公式。缺完整范围时返回 `unavailable`，不按舱室形心或面积猜长。
3. 甲板端点干舷直接用当前浮态计算，长度百分比使用明确的参考长度。
   横摇周期只在所选工况 GM、型宽和有来源的回转半径系数齐备时计算。
4. 动力页读锅炉事实、所选机械质量、煤/油绑定，以及显式指定的燃料、水和
   其他可变载荷分组。动力构型另有能源与传动类型事实；可变载荷不是第二份
   排水量。
5. 阻力支持按速度求轴功率，以及在提交速度网格形成有效包围时按轴功率
   反求速度。方法越界、无根或非主结果会说明原因。目标纵倾是独立的
   所需纵向力矩研究，不伪称已移动载荷或达到目标。

## 七页观察记录

`evidence/seven-page-binding-proposal.json` 已对原始 191 条逐项复核。
可执行的复核脚本是 `tools/plimsoll/tools/reconcile_seven_pages.py`；原先的
`pre_reconciliation_disposition` 保留，新的 `core_review` 指向实际路径与限制。
其中 26 条是先前批准的范围外项目，16 条是本轮后移的展示项；其余按已有绑定、
显式输入条件下可计算、尚无单独分项或方法待定义区分。
“有适配器”不代表 Queen Mary 有该行的史实输入。炮塔旋转装甲现在可作为
有来源的炮座质量子项单列，超过所选炮座质量时返回不可用；Queen Mary 没有
独立质量来源，因此仍显示未知。这一子项不进入固定装甲或排水量第二次计重。
SPS“自然速度”仍无约定定义。此前增量加入独立的装甲甲板平面覆盖率研究：
仅在覆盖面积与参考面积均有来源时计算 `100 × 覆盖面积 / 参考面积`。
这不是已验证的 SPS 原公式；Queen Mary 两项面积仍未知。

## 验证与交接边界

45 项逐条证据在 `evidence/core-acceptance-inventory.json`：27 项通过、
6 项按当前计算核心范围通过、8 项带明确限制通过、4 项按用户要求后移，
本地提交记录以 Git 为准。最新全量回归日志
`evidence/core-full-regression-after-increments.log` 记录
**700 项通过、0 失败、273.9 秒**，包含两个后续增量。
此前 `evidence/core-final-regression.log` 的 691 项通过是增量前基线。
`evidence/deck-coverage-focused.log` 记录覆盖率相关路径 **97 项通过**；
`evidence/mount-armour-focused.log` 记录炮塔装甲拆分相关路径 **116 项通过**。
首次合并回归在 Windows 中文子进程输出的测试运行器处出现 2 个 UTF-8 解码错误；
给该测试的子进程明确设置 UTF-8 后，定向复核和上述全量回归均通过。
原核心测试核对 Queen Mary 非零时长进水的
守恒、停止原因和剩余 GZ；通用二舱 60 秒请求在水力平衡容差内提前停止。

性能原始证据在 `evidence/core-performance-benchmark.json`。前六项测于
水力平衡修复之前，作为代表性耗时保留；修复后的通用二舱 **10 秒**场景
三次测量中位数 4.035 秒、最大 4.055 秒。原 60 秒三次压力测量接近
50 分钟仍未完成，已中止，不能算通过。根因是接近平衡时流向反转保护
不断把 0.5 秒步长折半到微秒级；现以明确的 1×10⁻⁸ m 水头容差停止，
返回真实的接受时长。用户已将长时压力测量移出本轮类 SPS 完成闸门。
