## 3. 三个必须带走的结论

1. **账本是唯一质量权威，页面行只能投影不能重算。** 装甲 7 行 / 13 条目合计 **6820.701 t == 账本装甲组**；
   武器鱼雷行 **62.0 t == 账本 weapons.torpedo 组**。旧的独立页面案例（`armour.py` 等）与自己算的 `area×t×ρ`
   是**平行副本**，不得当作第二真值来源。
2. **「缺值 ≠ 零」已经落到具体字段**：`mass_status="no_ledger_binding"`（无绑定行）、
   `segment_status="unknown_no_declared_extent"`（无声明跨度）、`typed_unknown_fields`（未知类型字段）
   —— 三处都显式报告，不再用 0 或猜测填充。
3. **数值收敛 / 处理完成 / 方法适用 / 史实验证是四个不同字段**：例如 QM 的阻力场景**全部**是
   `selected_plane_longitudinal_trim_proxy_v1` → `primary_result=False`、`model_applicable=False`；
   taylor 低速点出 `model_limit` + `taylor.outside_table` 并**把总阻力与功率置空**（宁可空着也不外推）。

## 4. 不变量与「拒绝编造」清单

**投影层诊断**（`page_rows.py`）：

| code | 阻塞 | 含义 |
|---|---|---|
| `item_duplicate` | 是 | 同一条目被两行引用（重复计重） |
| `item_unknown` | 是 | 声明了账本里不存在的条目 |
| `item_uncovered` | 否 | 账本条目未被任何行覆盖（列出 id） |
| `mass_mismatch` | 否 | 行合计 ≠ 该叶子的 `ledger_mass_t` |
| `item_mass_unknown` | 否 | 条目质量未知 → 行合计不完整 |
| `extent_invalid` | 否 | `extents_m` 未声明有限 `aft_m`/`fore_m` |
| `typed_field_unknown` | 否 | 类型化字段未知（列出字段名） |

**不做**：不按形心反推长度、不拿面积冒充跨度、不为缺数据的行补零、不发明未获批的算法
（「最小主装甲带长度」仍**无获批代理**）。

## 6. 环境与坑（会复发）

1. **git 必须带 `safe.directory`**（目录属主是 `CodexSandboxOffline`）。
2. **中文路径不要放进 shell 变量**再传给 git —— 本环境会破坏编码（报 `dubious ownership` 或路径乱码）；
   一律内联写全路径。
3. **模型额度 429**：2026-09-23 02:44 (UTC+8) 前后出现过额度耗尽，worker 会直接失败；
   额度受限时**主代理自己动手**比反复派单有效（本轮最后两项就是这样完成的）。
4. **Explore 型 worker 没有 `TaskOutput`**：给它派活时禁止起后台命令/轮询，否则会因
   `Tool TaskOutput not found` 直接挂掉（本轮踩过两次）。
5. **后台长时间任务要增量落盘**：性能基准原先只在最后写 JSON，被中断一次就白跑 2 小时；
   现在它**每个工作负载后都写**。同类的验证/测量脚本一律照此处理。
6. **写操作串行**：两个 worker 同时改同一测试文件会互相覆盖；不同文件才可并行。
