## 二、实测数字（146 案例，嵌套留一法）

| 口径 | MAPE | 中位 |
|---|---|---|
| 原程序口径（基线） | 15.93 % | 11.86 % |
| 原程序 + 按舰种因子 | 12.11 % | 10.55 % |
| 按 Cb 混合（零校准） | 11.86 % | 10.48 % |
| **混合 + 按舰种因子** | **10.62 %** | **8.24 %** |

按舰种因子：战列舰 0.923、航母 0.970、巡洋舰 1.020、驱逐舰 0.816（原程序口径）；
混合口径下驱逐舰变为 0.979 —— 说明该段的偏差主要是"用错方法"，不是"方法偏了"。

**同源移植对照**：对方"original"22.44 % → "Holtrop + 舰种因子"10.19 %。我们的基线是 15.93 %（高 6.5 点保真度），
校准后 10.62 %（差 0.4 点），而分段规则按船型而不是按舰种标签。

| 舰 | 试航记录 | plimsoll | 偏差 |

## 四、为什么第 4' 步受阻

1. 本机到 wikipedia 不可达，只能走服务端检索拿摘要，拿不到 infobox 的精确数字；
2. 中文引擎会把 HMS/USS 误判成华为移动服务等无关词；
3. **规模不成立**：手工核读可得的是个位数案例，而现有因子每组 32–44 条才成立。
   真正的出处已经定位（Hood 的 ADM 226/23、Bismarck 的验收报告、Dreadnought 的 1906 ASNE 论文），
   但要读档案、成规模录入，不是一次会话能完成的量级。

## 五、结论与建议

- 产品侧的可用成果：分段混合（可选场景）、可审计校准（`resistance_calibration`，带样本量与 LOOCV）、
  以及两条试航绊线测试；
- **不要把 10.62 % 宣传成"对真实军舰的精度"** —— 它是对一个混用了设计值与试航值的参考集的误差；
- 下一步的正确顺序：**先修数据，再调模型**。把 146 条参考值按"设计额定 / 试航实测 / 未知"分类，
  试航类替换为带档案号的数值，然后再谈校准与 LOOCV；
- 在此之前，分段混合可以继续用（它按船型分流，不依赖目标值口径），校准因子维持"可选、带出处、不宣称已验证"。
