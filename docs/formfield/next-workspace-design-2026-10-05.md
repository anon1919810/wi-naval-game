# Plimsoll 下一轮桌面设计提案 · 2026-10-05

状态：设计提案，尚未实现。本轮请求是设计下一步及整理更新日志；此文件不代表新界面已交付。设计依据为本地 `6ce11d9` 及当前页面代码。

## 目的与现状

下一轮让使用者在打开舰船后，能立即辨认正在编辑什么、当前工况是什么、哪些修改尚未保存，以及结果来自哪次运行。延续 Y’s Formfield 的精准、现代与高互动性；把注意力集中在输入和计算结果。

项目库已经完成两栏结构与列表化。工作台、运行页和报告目前主要继承了新的颜色、字体、细线与面板样式，信息结构仍有以下缺口：

- 编辑页的工具栏、舰名、工况条和章节说明各占一层；项目身份与当前操作的视觉权重接近。
- 多组表单继续使用嵌套框，说明占据较多空间；右侧 Trace 未选字段时仍显示通用提示。
- 概览与报告里的通用侧视示意图不是当前项目的精确几何，不适合继续承担主要展示面积。
- 运行页只预览前四个已请求阶段，报告是连续长页；破损虽然有专门结果入口，其他阶段仍缺少清楚的定位。

本轮沿用桌面范围、Space Grotesk 标题、Inter 正文、系统中文回退、浅深色主题及现有 API。结构标题优先英文，专业字段与功能提示延续当前中文口径。公开首页的扫描、俯视原稿和中央展台保留。

## 推荐顺序

### 第一组：编辑页工作头与输入层级

这是下一次实施的首选范围，可以独立交付和验收。

**工作头分两层。** 顶部低频信息放返回入口、项目定位和主题；工作区内的紧凑操作条集中工况、修订、保存状态、Save 和 Run。项目 JSON 下载归入次级操作。合并当前 Formfield 返回条与应用页眉的重复占高，保留真实返回目的地和已有转场锚点。

**标题随上下文变化。** Overview 保留醒目的舰名；进入 Hull、Weights、Damage 等章节后，章节标题成为主标题，舰名收为小号上下文。重要错误和修订冲突紧邻操作条，不能折叠进帮助说明。

**概览成为项目读数面板。** 用船型输入、当前工况、最新匹配结果和运行记录入口替代大面积通用侧视图。输入值明确标为 Input，保存结果标为 Result / Revision；没有有效匹配结果时显示尚无结果。暂不新绘船体、不把历史 Queen Mary 线图用于任意项目、不从输入拼出伪精确几何。

**章节采用一致的阅读顺序。** 简短用途 → 输入分组 → 可选研究请求 → 对应结果或报告入口。一级分组用编号与细线分隔，字段组减少重复外框。长方法说明与完整来源用可展开区域；输入错误、缺项原因和必要方法边界保持直接可见。

**来源靠近字段。** 已声明来源、工程估算和未知状态以小标识邻接相关字段。Trace 只展示实际选中的输入事实；未选中时保持简短引导。宽桌面可展开右栏，窄桌面通过明确的来源按钮打开同一信息，不挤压中间表单，也不遮挡当前编辑字段。不能将通用说明称为独立史料。

参考空间分配：左侧章节索引约 200px，中间自适应，展开的 Trace 约 240px。1024px 桌面默认收起 Trace。多列重量、甲板及高级输入保持局部横向滚动，页面本身不横向溢出。

| 区域 | 首要内容 | 次要内容 |
|---|---|---|
| 工作头 | 工况、修订、保存状态、Save / Run | 项目文档下载、返回 |
| 章节索引 | 当前章节与编号 | 静态定位线 |
| 中间输入区 | 当前章节、字段、必要错误 | 长帮助与方法说明 |
| Trace | 已选字段的来源与估算状态 | 完整文本与相关约束 |
| Overview | 输入摘要、当前匹配结果、运行记录 | 项目背景 |

### 第二组：运行与报告的阅读结构

第一组确认后实施，复用工作头、分组和索引样式。

**运行页先显示真实状态。** 显示排队、运行、完成、部分完成、取消或失败，以及工况和修订。请求指纹保留完整内容，但以可展开元信息呈现。运行中的反馈依据已有状态；现有接口没有逐阶段实时进度，不能据此画完成百分比或宣称某阶段正在执行。

有结果时提供已请求阶段目录，按现有阶段顺序定位摘要或完整报告。部分完成、取消前已存结果及失败原因保留各自语义。破损的停止原因、守恒证据和剩余稳性继续有直接入口。

**报告首屏压缩为身份、有效性与关键读数。** 舰名、工况、修订/运行、终态与史实验证状态形成紧凑封面；删除通用侧视占位图。重量、浮态、稳性、功率和续航等读数只取对应保存阶段的现有字段，先定义明确的字段投影和单位。缺项显示 Unknown / Unavailable 及原因，不补零、不新算总评分。

**侧面阶段索引配合连续正文。** 索引仅包含已请求阶段，点击滚动到对应章节，保留可复制的定位与键盘访问。正文默认可完整阅读，完整数据、诊断和来源仍可到达。必要警告随对应结果显示；长来源和指纹可折叠。打印时展开必需内容、移除导航与操作控件，浅深色均生成清楚的白底报告。

显示单位与导出放在安静的操作区。单位选择只改变本页呈现；项目 JSON 备份与运行 JSON / CSV 报告仍明确区分。现有对比保持兼容性检查及有限指标范围，不在版式改动中扩大计算口径。

### 第三组：功能转场与最后精校

只在阅读顺序稳定后加入，动效用于说明位置或状态变化，不拖延可操作时间。

| 操作 | 建议时长 | 行为 |
|---|---:|---|
| 工作台切章节 | 150ms | 中栏淡入及至多 4px 位移；工作头、章节索引固定 |
| Trace 展开或切换字段 | 180ms | 局部揭示；键盘焦点随用户操作进入相应内容 |
| Library → Workbench | 220ms | 项目定位与内容淡入；真实加载未完成时显示骨架 |
| Run → Report | 220ms | 保留运行身份上下文，结果正文出现 |
| 报告阶段定位 | 浏览器滚动 | 不对长正文逐段动画，不制造反复进入效果 |

以上是待实施时序，不替代公共页面已有的 2500ms Splash、360ms 换图、400ms 作品详情转场与 450ms 工具往返。实现前用 MDN 官方文档或可用的 MDN 连接器核对所用 API 和降级方式。

章节切换不得为了动画重建持有草稿的 Workbench，不能丢失焦点、文本选择或尚未保存的输入。页面数据异步到达时拒绝旧请求，不人为延迟已就绪内容。启用 `prefers-reduced-motion` 时直接展示终态；不增加动画库或每帧 React 状态提交。

## 必须守住的数据行为

- 未保存、无工况、正在操作或研究请求有错误时，沿用现有运行限制；409 修订冲突的草稿复制与重载路径保留。
- JSON 应用只是草稿修改，仍须保存。单位切换和来源展开不得把项目变成已修改状态。
- 当前结果必须匹配项目、已保存修订及工况；修改输入后不能继续将旧运行称为当前结果。历史记录可以查看，但身份必须明确。
- `queued / running / completed / partial / canceled / failed` 与取消已请求状态分开。计算完成不代表安全、适航或史实认证。
- 未知、不可用、未请求及方法越界与零值分开；严重诊断不被交互折叠隐藏。
- 报告读取不可变保存结果；显示单位不改快照、请求指纹、方法版本或规范单位导出。
- 匿名浏览器身份、项目保存和备份说明保留；不新增登录、同步或自动恢复承诺。
- 辅助线只用于留白、章节定位和细分隔，不穿过字段或数据图，不伪装工程刻度。

## 验收安排与发布条件

按两组功能集中验收，不在每个小改动后跑全量测试：

1. 第一组完成后运行相关工作台、表单与保存/结果身份测试；浏览器检查 1440×960 和 1024×900 的浅深色、键盘输入、来源展开、修订冲突、长字段和局部滚动。
2. 第二、三组完成后集中检查运行/报告组件与转场：真实终态、部分结果、取消、无结果、单位显示、报告对比限制、reduced-motion、导航返回和焦点保持。
3. 冻结后执行一次前端全量回归及构建，再检查一份现有已保存报告的打印/PDF。若没有可用的已保存结果，只新增一次受控基线计算；不为视觉验收重复完整计算核心性能测试。

关键通过标准：工况和修订一眼可见；操作条不重复占高；修改后旧结果立即失去“当前”身份；主要状态和缺项有明确原因；Trace 不遮输入；两种桌面宽度无页面横向溢出；打印不漏诊断与来源。

当前并行字体会话还有未提交资产与全局样式。发布前必须先整合这些成果，确保干净检出的字体与本地预览一致。本轮设计文档没有合入、覆盖或提交那组改动。最终上线沿用既有部署流程，届时另做公网验收。
