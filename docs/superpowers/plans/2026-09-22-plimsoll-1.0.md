## Shared contracts

Canonical `plimsoll-project-1` is defined by `docs/plimsoll-1.0/data-contract.md` in Task 1. Later tasks extend it via explicit schema-preserving optional sections and validation; breaking changes require a migration.

Public API pipeline:

```python
project = project_io.normalize_project(payload)
state = loading.resolve_loading(project, condition_id)
result = analysis.compute_project(project, condition_id, options=None)
job = service_jobs.submit(project, condition_id, options=None)
```

`state` includes effective weight items, total mass and full x/y/z moments, missing data diagnostics, source/estimate summary, and `input_fingerprint`. `result` includes matching fingerprint, diagnostics, validity, loading, hydrostatics, stability, resistance, optional damage and calculation trace. Task 1 establishes project I/O only; later functions must not be stubbed as though implemented.

Diagnostic shape: `{code, severity, path, message, blocking}`; severity is `info|warning|error`. Lists remain structured through all callers; legacy string warnings can be represented as diagnostics retaining their exact meaning.

## Task 1: Canonical project, units, diagnostics and migration

**Files:** Create `tools/plimsoll/project_io.py`, `units.py`, `tests/test_project_io.py`, `docs/plimsoll-1.0/data-contract.md`.
**Interfaces:** `units.convert(value, from_unit, to_unit)`; `project_io.new_project(name, project_id=None)`; `validate_project(payload)->list[dict]`; `normalize_project(payload)->dict`; `migrate_legacy(ship, weights=None)->dict`; `input_fingerprint(project)->str`.

Project fields: schema, id, name, revision (nonnegative integer), units, coordinates, hull, geometry, weight_groups, loading_conditions, systems, compartments, openings, sources. Canonical project values are SI as named; alternate display/import units use `units.convert` explicitly, never silently reinterpret a `_m` field as feet.
Default units: `{"length":"m","mass":"t","speed":"kn","power":"kW","angle":"deg"}`. Coordinates: `{"x_positive":"forward","x_origin":"midships","y_positive":"starboard","z_origin":"keel"}`. Geometry nullable or explicit kind/source/estimate/keel offset with offsets payload or reference parameters. No hidden repository path scan. Hull can contain existing dimension fields, and nullable unknowns.
Groups: `{id,label,required,items}`; items: `{id,mass_t,x_m,y_m,kg_m,source,estimate,uncertainty?,includes?}` with all four numeric values nullable. Mass nonnegative, x/y signed, KG nonnegative. Unknown or source-free data receives a diagnostic, not an invented value. Item IDs unique across groups; group IDs and loading IDs unique. Loading entry: `{id,label,reference_displacement_t?,overrides:{item_id:{mass_t?,x_m?,y_m?,kg_m?}}}`. Only present overrides replace values; reject unknown item IDs. System payloads remain separate until Tasks 3/7.
`new_project` creates an editable empty draft, not a valid full ship. Validation distinguishes draft incompleteness warnings from malformed payload errors. `normalize_project` deep-copies, supplies only schema defaults, rejects malformed payloads with a ValueError subtype carrying diagnostics; it must not zero unknown mass/CG, overwrite source values, or mutate its argument. Reject unsupported schema versions.
Migration reads existing `plimsoll-ship-1` plus optional `plimsoll-weights-1`, preserves all original source data under `legacy_inputs`, copies hull fields, adds normal/deep loading references and missing x/y diagnostics. Known mass unit conversion is explicit; legacy unconfirmed tonnes remain marked estimated, not declared measured. Do not fabricate fuel load differences. External offsets references may remain an unresolved typed reference until materialized by the project loader.
Fingerprint: SHA-256 of stable canonical JSON, no NaN, independent of dictionary order; any actual project-input change changes it. Stored result/cache keys are excluded or rejected as outside canonical input, so a result cannot change its own input hash.
