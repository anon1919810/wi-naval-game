# Design feedback and responsive workbench — 2026-10-18

The user authorized autonomous design and a substantial implementation batch, fewer repeated checks, and one consolidated acceptance at the end. Build on the already isolated, clean `feature/plimsoll-1.0` checkout at c59a47e. No additional approval gate is needed for this agreed scope.

## Goal

A designer editing the unified native ship design can see what changed relative to the saved revision, which existing result readings moved, whether a preview is still being confirmed, and can compare two frozen native runs without reading the full technical report. Opening the project library must not load all of Workbench and Report.

## Contract

1. **Draft changes against the saved revision.** Add a compact accessible panel to native Workbench, near the shared toolbar/overview and reusable in weights. Baseline is the actual `view.project` saved revision, never an older selected run or optimistic input. Read a baseline preview through the pure `/api/design/preview` adapter once per saved project/revision/document identity, with bounded caching and stale-response guards. No writes, auto-runs or fabricated local ship calculations. A loading/failed baseline offers retry and leaves all input usable. Saving resets the comparison to the new saved revision; project switch/unmount discards old responses. Initialization/import of a previously non-native saved project is clearly named and has no invented numeric baseline.
2. **Readings.** Show finite before/current/difference for selected ledger mass, source estimated mass, target displacement, balance gap, maximum speed, source horsepower, endurance range, source empirical stability and available source hull strength (discover exact existing path). Label empirical stability explicitly, never GM. Mass uses recorded metric tonnes, speed kn, source hp/nmi stay their own units; existing display-unit helpers may convert only declared dimensions. Baseline zero allows absolute delta and no percentage; missing/null/non-finite stay unknown, never zero. Method/schema/basis mismatches prevent numeric differences. Pending or failed preview never presents old readings as the latest draft.
3. **What changed.** Summarize changed native parameters with catalog labels and their actual units/scales, changed ledger roles and estimated/declared policy. Include manual mass changes from ledger, not just parameters. Rank up to five changed role masses by absolute difference with an expandable rest. Call these observed contributions/changes, not a sensitivity analysis or proof of causation. Changes that result from source coupling may be listed as such only where recorded; otherwise no causal attribution. No optimistic derived numbers. Add chapter links where the existing source-page mapping supports it.
4. **Frozen comparison.** In existing Report comparison, add a concise native summary above the full readings, using only the two immutable `RunView.result` and `result.input_snapshot` values. No calls to live preview for historical comparison. Compare only same-project, matching native schema/method, same native basis condition, readable completed/partial stages; withhold individual unknowns. Different physical requested stages do not invalidate native readings but explain that optional physical results differ in scope. Include the selected run/revision identities, signed numeric changes, changed inputs and role masses, no global green/red better/worse verdict. Keep existing complete comparison and original report identity protections.
5. **Responsive input feedback.** Reuse the existing serial queue, optimistic INPUTS, confirmed RESULTS and source event order. Show a restrained accessible status for confirming N edits / up-to-date / failed with retry. Save/run remain blocked until pending requests finish; keep edits and manual choices after failures. No debounce, request coalescing or last-write-wins changes that skip original event/cache semantics. Input focus, scroll and unsaved JSON must survive chapter/language changes.
6. **Route loading.** Lazy-load Workbench and Report (and Run only if useful) from App using named-export adapters. Keep Library interactive without these bundles. A visible loading and localized recoverable chunk-error state must preserve shell/session/navigation. Retry must actually reattempt failed imports, not reuse a rejected lazy promise. Avoid remounting mounted drafts during theme/language changes, preserve leave guards. No new dependencies/config hacks or deleting features to lower bytes. Consider splitting an expensive optional chapter block only if necessary after route splitting.
7. **Style/copy.** Fit the current glass style and dense workspace. Chinese and English complete, keyboard readable, correct aria status, no internal implementation jargon in UI. 390px layouts scroll tables within their panels rather than widening the page. Prefer concise summary with expandable details over another wall of numbers.
