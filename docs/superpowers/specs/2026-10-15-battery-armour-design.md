# 炮座装甲经验估重增量

用户已授权自主推进报告剩余覆盖项。沿用当前 linked worktree 和 OpenCode 实现、Codex 独立验收，不再等待离线用户选择。以下接口和边界是本轮实现决定。

## 目标与边界

闭合 F04 中炮罩/炮塔及炮座筒装甲的厚度修改、自动估重、审阅采纳和保存重开。它是独立经验估计，不是装甲几何重建、物理强度或全套 SPS 布局恢复。本轮不改 `.sship` 映射，不从原文件归档自动启用假设，不填 CG、不自动采纳、不补差。原生下载的环境阻塞继续单列，不据其修改产品。

来源：本聊天 `outputs/SpringSharp3b3-recovered/SpringSharpMono/GunControl.cs:1127-1294`，`armWeightCalc`、`diameterCalc`；原程序 SHA256 `82ecc3fedf76af222dd13ad68258f3ae92146e9fad7dc6a4a96f3270fccf71fc`。本轮独立运行原始方法产生受控数值，不把其视为整条事件链或实船验证。仓库不复制反编译 C#。

## 可选输入与兼容

`concept_design.batteries[i].armour` 省略或 null 时，旧工程和结果保持原行为。启用时对象仅接受：

- `system_id` / `item_id`：独立系统叶和其拥有的重量项；与任何其它部件目标唯一，不把已有炮座质量再次算一份。null 可保存为未完成输入，不产生建议。
- `face_mm` / `rear_roof_mm` / `barbette_mm`：毫米，有限 0..1000；null 未知，不能等于未装甲的 0。
- `freeboard_m`：炮位加权甲板干舷，米，有限 0..100；不是重心，也不自动取代表性全舰干舷。
- `super_factor`：原算法 `super` 的显式经验高度系数，有限 0..10；不从布局或物理横倾推导。

后两项仅在 `barbette_mm > 0` 且原算法对应炮座筒系数非零时必需；0 厚度或无该部件的炮座类型不应因缺少无关输入而失去炮罩估重。缺必需数值只生成不可用诊断，错误类型/负数/超域/非整数计数拒绝，不静默修正。与现有炮身/炮座/弹药估重独立：弹药输入缺失不能阻塞装甲估重，装甲缺失不能阻塞原有估重。

源控件 `armBack` 的提示为 “Average side / top thickness”（:2251），`armBottom` 为 “Barbette / below deck thickness”（:2243）。接口保留上述名字，但 UI 与来源必须称“侧面/顶部平均厚度”和“炮座筒/甲板下装甲厚度”，不能把 armBack 只说成后部装甲。干舷输入必须先换为 `freeboard_ft = freeboard_m / 0.3048` 才代入源 freeGun 公式，原生数值验证会检查这一点。

只支持单列炮架的单一、同构炮组行，每座 1..5 门；共享炮架仍为 2..5 门。源选择项的单炮为 0；2..5 门的共享型为 3/6/9/12，非共享型为 4/7/10/13；不覆盖 1/2/5/8/11/14 的多列炮架。已有 6..10 门炮组仍可保存及估原有部件，只有该装甲估重返回不支持。两种炮组不得为了本估计擅自合并。本轮不宣称混合组或多列炮架总装甲与原程序一致，界面和来源均需说明单列范围。

## 计算身份

新增纯模块 `tools/plimsoll/battery_armour.py`，`METHOD_VERSION = "sps-3b3-battery-armour-v1"`。
入口 `estimate(calibre_mm, year, gun_type, mount_type, mount_count, barrels_per_mount, shared_cradle, face_mm, rear_roof_mm, barbette_mm, freeboard_m=None, super_factor=None)` 返回 `values`（face/back/barbette/total_long_tons、直径与炮罩高等）和 `provenance`。

保留来源的口径英寸、直径英尺、装甲英寸、0.0185 经验质量常数、机枪/高炮分支、炮罩高分支、共享炮架直径折减、炮座筒系数平方及年代第四根。不得按“更合理”的几何改写。源整数平均的语义在同构行中等于该行每座门数。总量必须有限、非负；溢出转为结构化不可用诊断。

使用现有 `empirical_estimate_v1` 与 `_model` 生成单一 `concept.<battery id>.armour` 建议；该模型的 `inputs.method_version` 与 `source.method_version` 使用独立部件版本，附原程序摘要、位置和显式假设，沿用采纳记录已有的方法身份字段。上层 `sps-3b3-adapted-v1` 配置身份和旧模型身份不改；新模块身份进入实际验证源码清单。

## 唯一账本与设计平衡

炮座筒并非旋转装甲，故新增设计角色 `gun_mount_armour`（炮罩及炮座筒装甲），不能把整个估算标成 `rotating_armour`。新目标在 balance 启用时必须归属该角色。旧 `rotating_armour` 继续表示已有旋转装甲。

原算法 gun `armWeight` 对应的需求、强度、空间计算使用两者的和；机械排水量扣除中的装甲总量各计一次。已有数值不变；报告说明新总量口径，不能把其中固定炮座筒称为旋转部分。用户若已将同一装甲包含在另一部件，必须先拆分目标；不自动从手工炮座质量扣除，也不自动生成拆分。

## 网页

现有概念设计炮组卡新增可选装甲估重块，普通输入编辑上述字段。系统变更只清除本块 item 绑定，不改其它部件。关闭仅移除 armour 输入；保留已有账本质量和采纳记录。EN/ZH 文案齐全，毫米和米按现有单位控件契约转换，不引入全局样式。说明显式假设及单独计重要求。现有建议面板负责审阅、勾选和原子采纳，不新建旁路。角色快捷分配识别新目标。

## 验收

原程序独立数值覆盖 7 种炮座、7 种炮种、1..5 门、共享炮架、年代、无装甲/仅三种分量、干舷/高度边界；相对容差 1e-5、近零绝对 1e-7 LT。独立读取源码比对关键分支，兼容数值与工程验证分开。

集成检查旧项目无变化、缺项可保存和独立估重、目标归属/重复/角色拒绝、厚度变化建议变化、显式采纳只改变当前工况覆盖、基础重量和其它工况/迁移原始归档不变、过期建议拒绝、JSON 往返。浏览器隔离数据库验证普通表单修改、真实 worker 生成建议、采纳、保存重开；原生下载仍按已有环境限制单列。
