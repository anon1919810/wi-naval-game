# SpringSharp 3.0 project migration design

User authorized the next F07 implementation after F08/F06 acceptance. Codex owns design and independent acceptance; OpenCode implements. Existing linked worktree and all dirty work remain in place; no commits, staging, resets, deployment or dependency installation. The following are implementation decisions within the requested migration, not new user requirements.

## Outcome and boundaries

Read a SpringSharp 3.0 `.sship` (or same-header `.dat`), show mapped values and missing information before creating anything, then explicitly save a new canonical Plimsoll project. The new project can be edited, calculated to the extent its inputs support, saved/reopened and exported through existing workflows. Original bytes, all fields, notes and conversion provenance survive canonical export/reimport. No default geometry, CG, material density, inertia, ballast, full weight ledger or claim of historical validation is manufactured.

Support exact headers `SpringSharp Version 3.0` and `SpringSharp Version 3,0`, 280 positional fields, then an arbitrary notes tail. Reject 2.0/1.x/unknown versions with a useful diagnostic; their field meanings differ. Source: recovered `MainForm.cs` openFileCalc and save handler; original assembly SHA256 `82ecc3fedf76af222dd13ad68258f3ae92146e9fad7dc6a4a96f3270fccf71fc`. Recovered code stays outside product source. The field evidence JSON is in chat outputs/Plimsoll-sship-migration-2026-10-15/format-evidence.json. There are no discovered user `.sship` samples in Desktop/Downloads/Documents so far. Controlled samples must be labelled synthetic, not real ship migrations.

## Core interface and archive

New `tools/plimsoll/sship_import.py` (may use a focused `sship_fields.py` registry and `sship_mapping.py` projection module):

`preview(data: bytes, *, filename: str = 'ship.sship') -> dict`

Return `{schema:'plimsoll-sship-preview-1', method_version:'springsharp-3.0-migration-1', source, project, fields, counts, diagnostics, limitations}`. Errors raise `SshipImportError(ValueError)` with structured `diagnostics` containing code, severity, path, message, blocking and source line/index where applicable. No I/O, execution, network or global locale changes inside the importer.

`source` contains basename-only filename, exact SHA256, byte length, encoding, header, version and decimal_separator. `fields` has exactly 280 ordered records `{index,line,name,raw,disposition,destinations,reason}`; disposition is mapped/preserved/duplicate/reserved. Counts sum to 280. A field used in a derivation lists its target and the derivation basis; an archived field is not counted as an active mapped value.

Project top-level `migration` archive contains schema `plimsoll-sship-migration-1`, method_version, source, `original_base64`, `raw_fields` (280 exact strings), `notes` (exact decoded tail), field mapping and migration diagnostics/limitations. This is evidence, not computed results. Existing JSON project normalization preserves this JSON-compatible top-level section. Deterministic source project ID is `sship-` plus SHA256 prefix; server save still creates its own UUID/revision. Blank ship name may fall back to the source filename stem with an explicit note. Supplied nonblank name remains source text. Estimate provenance remains unknown for imported declarations, true for generated empirical estimates.

Maximum raw input 1 MiB, field line length 4096 characters, numeric token length 128; reject limits before expensive parsing. UTF-8 with/without BOM and BOM-marked UTF-16 LE/BE are supported; all decoding strict. Use only CRLF/CR/LF as record separators, preserve the notes tail, do not use Unicode splitlines semantics to split names/notes. Exactly 280 parameter records are needed; a missing final newline alone may be accepted. Empty numeric fields are unknown; real zeros remain zeros. Reject invalid populated numeric/boolean/enum syntax and NaN/Infinity/overflow with line diagnostics. Source numeric decimal convention comes from the header, independent of machine locale. Accept correct thousands groups using the opposite punctuation, or ordinary/NBSP/narrow spaces, and scientific notation; reject ambiguous/malformed grouping instead of guessing. Text fields and notes are never punctuation-swapped.

## Semantic mapping

Use the recovered 280-position registry, not inference from labels. Positions 247..279 are ignored padding in the original reader: preserve them without treating them as parameters. For the duplicated group-mount values, positions 211..235 take precedence as the original loader does; preserve both occurrences and warn if their interpreted values differ. Missing latest value must not silently fall back to an earlier value. Scale selectors normally save 0/1; hull 2/3 are commands that reset scales and are not stable saved units: reject unsupported saved selectors explicitly rather than treating all nonzero values as metric.

* Hull scale 0 means ft, 1 means m. Map LWL[13], moulded beam[14], normal draught[15], Cb[17]; preserve bulged beam[127] separately in archive and derivation provenance. Map country/type/hull year/engine year to sourced metadata facts. Unknown/out-of-target-domain nonnegative declarations may remain archived with visible warning and null target; negative dimensions, malformed types and nonfinite values are errors. Do not clamp or treat an explicit zero as a secretly supplied positive input.
* Gun calibre uses each battery's scale[4..8] (in or mm). Saved shellWeightBox[36+6*i] is **always pounds**, even with metric calibre: convert to kg. Five bank descriptions, counts, dates[129..133], barrel lengths[140..144], ammunition[61,145..148], mount and gun types map to editable weapons facts/page rows, with unknown masses/positions. Do not equate total barrels and mounts.
* Original per-mount index table is `[1,2,4,2,2,4,3,3,6,4,4,8,5,5,10]`. Total mounts are [62,65,68,71,74]; G2 count is final super+deck+sub fields [221+i,226+i,231+i]; G1 count is total minus G2 (its deck count is implicit). A valid source bank may become separate G1/G2 canonical batteries to retain different barrels-per-mount/shared-cradle meanings. Shared cradle indices are 3/6/9/12. Check nonnegative count consistency and total installed barrels against both groups before enabling a concept model. Inconsistent or unsupported layouts remain visible, preserved drafts, not silently reinterpreted models. Do not invent broadside eligibility from placement labels.
* Armour thickness uses armour scale[10] (in/mm); armour lengths/heights/beam also use armour scale[10] (ft/m), independently of hull scale[3]. This corrects the initial design after checking recovered ArmourControl.cs handlers at lines 455, 462, 474, 480, 492, 498, 516, 522, 534, 540 and 556, which pass that control's scale.SelectedIndex to feet2metres conversions. Map recognized belts, bulkhead, bulge, deck and conning facts/page rows to existing armour schema. Preserve coverage enum, turret armour, placement and unsupported shape details with diagnostics; never invent density/area/weight from absent geometry.
* Speeds[109,110] are knots, range[111] nautical miles, shafts[112] count. Fuel/engine/drive flags remain distinct; map explicit propulsion descriptions and dates. A sourced empirical machinery/fuel config may be enabled only for the existing supported steam-kind and coal/oil domain; no diesel-to-steam coercion. Missing shaft power remains null. No historical propulsion fact is synthesized.
* Misc weights[12,198,199,200,246] are **long tons regardless of hull/armour display units** (each original method calls fpCheck with Con.none). Convert via 1 LT=1.0160469088 t. Unknown positions stay null. Include an unknown structure/remaining-weight placeholder so five misc values cannot masquerade as the complete ledger. Imported geometry stays null, opening definition unknown, no compartments/openings created.

Populate optional concept_design with supported battery parameters and existing machinery/fuel methods so the imported design can use existing estimate-review/adoption actions. All proposed masses start unadopted, their ledger masses null. If a bank is out of the existing empirical model's supported domain, map its editable facts/archive but omit its model with a diagnostic; do not reject the whole otherwise interpretable file. Do not add balance layout/strength assumptions. `balance` remains null, explicitly missing. Raw broadside count remains null: the existing estimator's internally labelled installed-count fallback is a screening assumption, not a source eligibility fact, and no balance screen is enabled by this import. Disclose that limitation and any moulded-versus-bulged beam adaptation in existing machinery models.

Normal displacement is **not stored** by this writer. When LWL, bulged beam, draught and Cb are known and valid, the source's `L_ft*B_bulges_ft*T_ft*Cb/35` LT may be recorded as a derived reference/target with its formula and field sources, never as ledger mass or measured displacement. Do not substitute moulded beam for a missing bulged beam. Representative concept freeboard, if needed, may be derived only from all valid source profile heights/fractions with the original formula: FC=.6*FCaft+.4*FCfore; the other three segments average endpoints; lengths fc[26]/100, fd[23]/100, qd[20]/100, ad=1-fc-fd-qd. State derivation, do not create physical deck coordinates from it.

Acceptance integration ruling: create one explicitly generated working condition with null mass reference and empty overrides, so the existing estimate workflow is usable without inventing a historical loading condition. Independent gun and fuel proposals may be reviewed and adopted. The existing speed-to-machinery method requires a declared balance screen when shaft power is unknown; this import keeps both power and balance unknown, so machinery weight remains unavailable until the user supplies those inputs. Preserving the missing-data boundary takes precedence over generating a fifth estimate from unstated assumptions.

## CLI

`python -m plimsoll import-sship INPUT --output converted.project.json [--name NAME]`

`python -m plimsoll import-sship INPUT --preview --output migration-preview.json`

Default output may be stdout. Preview produces the full core preview; normal mode produces only canonical project JSON. Reuse structured CLI errors; reject input/output aliases including hardlinks and existing/symlink destinations for this new command. Never overwrite an input or existing project. Invalid input creates no output. No changes to verification publication logic.

## Backend and frontend

Add authenticated, CSRF-protected JSON endpoints before `{project_id}` routes:

`POST /api/projects/sship-preview {filename, content_base64}` -> standard ProjectImportPreview fields plus optional `migration` containing source, method_version, fields, counts, diagnostics, limitations. No project/revision/run writes. Source data decoded with strict base64 and raw 1 MiB bound. Response does not need the full converted project.

`POST /api/projects/sship-import {filename, content_base64, source_sha256, name?}` -> existing ProjectView. Reparse source server-side, require its computed SHA256 to equal the supplied current-preview source_sha256, then call existing projects.import_project. Reject mismatched digest with HTTP 409 before writes. This is stateless content binding against stale selection, not proof that a human previewed anything; a legitimate API caller can provide matching new bytes and digest. A preview's client-supplied mapping/project is never trusted. Return fresh owned UUID/revision 1; source archive preserved.

Extend existing ProjectImport section with a separate SpringSharp chooser, preserving the existing JSON chooser/labels/flow. New `sshipFile.ts` encodes bounded original bytes to base64 without interpretation. `.sship`/`.dat` button accepts those extensions; format still verified server-side. Reuse the current busy lock, ticket/unmount protection, cancel/reselect/name/duplicate-save behavior. New selection discards the previous source/preview immediately. Saving uses the same frozen original bytes, not reparsed browser text. JSON backups remain compatible.

Show supported version, source filename/hash, mapped versus archived counts, missing geometry/ledger/CG and unsupported semantics before save; field detail is collapsible. React text rendering, no HTML interpretation. Keep copy Chinese/English, existing form style and unit conventions; do not redesign the library. No UI dependency/config/style overhaul. Export/reimport the migrated canonical JSON with original bytes/archive intact.

## Acceptance

Meaningful red/green unit tests cover positional/deduplicated semantics, original locale grouping, independent imperial/metric units, shell lb and misc LT traps, blank vs zero, raw byte/notes preservation, malformed/unsupported/truncated/oversized inputs, no mutation/I/O, import-normalize-export-reimport equality and honest unavailable physical calculations. CLI exercises preview/conversion and source/existing-output/hardlink protection. API proves preview creates no rows and save reparses/source mismatch cannot be forged; authentication/CSRF/bounds/owner isolation remain.

Browser acceptance uses real chooser -> preview -> cancel/reselect -> name -> save/open -> edit -> calculate/estimate -> canonical export/reopen. No live user project is modified; use the existing isolated scratch SQLite harness. Independently inspect mappings and missing-data display, preserve original hashes and F08/F06 files. Baseline first, then appropriate core/backend/frontend regressions and build, final independent reviewer. Clearly distinguish controlled source-derived/assembly-read fixtures from any real user file. Do not claim complete 2.0 compatibility or full SPS parity.
