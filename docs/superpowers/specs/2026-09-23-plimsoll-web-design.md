# Plimsoll Web：产品与视觉设计

日期：2026-09-23。状态：供用户审阅的设计稿；不是已实现的网站。

## 目标与已确认的边界

Plimsoll 要把现有类 SPS Python 计算核心变成可供多人各自使用的网站。用户通过邮箱一次性验证码自行注册或登录，创建、编辑、保存自己的舰船项目并选择工况，运行计算、查看可解释结果，最后在站内阅读报告。首版各用户的项目、结果及报告默认且始终私有；没有分享链接、协作编辑、QQ 登录、Unity 接入或 Windows 安装包。浅色主题为默认，用户可将偏好改为深色。中文为首版界面语言，数据内部仍遵守现有 SI 单位、坐标和英文键名契约。

网站的成功标准不是“能展示 15 个阶段”，而是用户能从项目库进入一个工况，知道哪个结果可用、哪个值只是估算、哪个输入缺失，并能保存、重开和复核同一请求。计算结果的 `completed` 不代表历史验证通过。Queen Mary 工程代理案例必须继续保持其来源与估算界限。[现有计算契约](../../plimsoll-1.0/analysis-api.md)和[输入准备度](../../plimsoll-1.0/queen-mary-input-readiness.md)是界面的事实来源。

## 取舍过的方案

1. **推荐：React/TypeScript 静态前端＋薄 Python API＋独立计算进程。** 前端适合实现键盘操作、密集编辑、图表与浅/深色主题；API 负责认证、项目归属、持久化及任务状态；计算进程原样调用现有 `compute_project`。三者边界清楚，浏览器刷新不会丢失计算任务。首版只部署一个应用实例与一个受限计算工作进程。
2. 服务端模板页面＋少量 JavaScript 可以更快做静态展示，但复杂账本编辑、对比视图和交互图表会逐渐变成分散的脚本。它适合作为临时演示，不作为正式产品路线。
3. 全前端本地计算会复制 Python 算法与数据契约，增加结果不一致风险，不采用。

这是一份设计选择，不指定最终前端组件库或邮件服务商；实现计划在本稿获批后再定。首版采用 PostgreSQL 保存账号、项目修订、计算任务与不可变结果，以数据库任务队列和单个工作进程起步，不额外引入 Redis。文件与计算结果由服务端管理；迁移、备份、事务和逐用户访问控制是上线条件。工作进程数量应由真实任务耗时和 2 GB 服务器内存测量决定。

## 信息架构与主要流程

1. **邮箱入口。** 输入邮箱 → 接收一次性验证码 → 验证 → 建立安全会话 → 进入项目库。注册与登录为同一入口。验证码有时效、单次使用、发送及尝试限制；对未注册邮箱和已注册邮箱给出同等的外部反馈，不泄露账号存在性。会话使用服务端管理的安全 Cookie；正式公开登录前必须验证 HTTPS。界面不让用户提供 QQ 密码、邮箱密码或服务器凭据。
2. **项目库。** 显示本人项目、最近计算、草稿状态和创建入口。可从空白项目、解析方箱、通用船或 Queen Mary 工程代理模板开始；模板卡片直接说明“解析基准”“通用试验船”或“史实未认证代理”。项目列表不混入其他用户的记录。
3. **舰船工作台。** 左侧为项目章节（概要、几何、重量与载荷、装甲武备、动力、浮态稳性、阻力功率、破损）；顶栏始终显示舰船、当前工况、保存状态和运行按钮；中央在表格、曲线和剖面之间切换；右侧检查栏显示当前值的单位、来源、估算说明及诊断。`Ctrl/⌘ K` 可搜索项目、工况与常用命令，但每项操作都保留可点击入口。
4. **计算记录与比较。** 修改输入形成新的项目修订；运行时固定输入快照、工况与规范化请求，形成不可变计算记录。较长计算在受限队列执行，显示真实阶段状态和取消结果；刷新页面后可重开记录。比较视图只比较同定义的单位与工况，明确显示方法版本和适用性差异。
5. **站内报告。** 由某次不可变计算记录生成，章节依次为摘要、输入与来源、重量/浮态、稳性、阻力/功率、续航、破损和诊断。未请求章节不出现伪结果；不可用章节说明原因。首版站内报告适合打印，PDF 导出在报告排版验收后再接。现有 JSON/CSV 导出继续可用，不被报告替代。
6. **账号与偏好。** 管理邮箱会话、主题、默认工况偏好和本人数据导出。用户删除项目时同时处理所属修订与结果；保留备份与恢复策略由运维设计明确。

## 视觉概念：“Datum / 基准线”

品牌标志来自吃水标记与参考水线：一条精确水平线穿过简化圆弧，作为 Plimsoll 图形线索。它只是视觉标记，不宣称为历史官方载重线。导航和按钮采用 Apple 式清晰层级与触控目标；工作台沿用 Linear 式安静侧栏、稳定位置、紧凑但可扫描的列表。舰船领域的独特性来自纵向站位、剖面线、水位变化和来源语义，而不是仿旧纸张或舰桥仪表装饰。[Apple 排版原则](https://developer.apple.com/design/human-interface-guidelines/typography) · [Linear 界面层级复盘](https://linear.app/now/behind-the-latest-design-refresh)

可审阅的工作台视觉稿：[浅色预览](assets/plimsoll-datum-workbench.png)／[矢量源稿](assets/plimsoll-datum-workbench.svg) · [深色预览](assets/plimsoll-datum-workbench-dark.png)／[矢量源稿](assets/plimsoll-datum-workbench-dark.svg)。两张图用于讨论层级与色彩；其中曲线和未运行页面的状态为排版示意，不是实际计算结果。

| --- | --- | --- | --- |
| 页面背景 | `#F5F7F8` | `#0F1921` | 留出清楚的工作面 |
| 面板 | `#FFFFFF` | `#18252E` | 编辑与报告内容 |
| 主文字 | `#182A34` | `#EAF0F3` | 正文与关键数值 |

界面使用系统无衬线字体栈，数字启用等宽数字；舰名与章节可有更宽松的字距，计算数值不使用装饰字体。正文、表格、图表和导出报告保持同一信息层级。浅色是首次进入的默认设置，深色由用户主动切换并随账号保存；报告采用浅色打印样式。动效只帮助确认焦点、工况切换和展开关系，尊重减少动态效果的系统设置。对比度、中文长标签、键盘焦点与窄屏排列需在设计验收中实测。

### 状态即视觉语言

| 数据状态 | 图形规则 | 必备文字 |
| --- | --- | --- |
| 有来源的已知值 | 实线标记 | 来源与单位 |
| 工程估算 | 虚线或斜纹标记 | “估算”及依据 |
| 未知或未提供 | 空心标记；数值处显示破折号 | “未知”或“未提供”，绝不显示 `0` |
| 方法不适用 | 中性斜纹区域 | “超出方法适用范围”及具体原因 |
| 失败／需修正 | 高对比诊断条 | 错误位置、影响范围和可执行建议 |

颜色不是唯一编码；黑白打印与色觉差异下仍能辨认。结果页应始终同时展示“计算完成状态”和“模型适用／史实验证状态”，不把 `completed` 渲染成“船舶安全合格”。

## 页面布局与响应策略

桌面工作台是主场景：低对比左导航、中央可伸缩工作区、按需展开的右检查栏。概览页首先显示舰船名与工况，再显示排水量、吃水、GM、阻力／功率等**当前请求确实有值**的摘要，下面是船体纵向示意和阶段结果。表格在需要输入精度的页面使用紧凑密度，编辑字段明确区分值、单位、来源和估算状态。报告页从工作台退出到较宽的阅读列，并允许返回对应输入与计算记录。小屏优先支持项目库、报告和结果阅读；复杂账本编辑明确以桌面宽度为主，但不得出现无法提交或看不到错误的位置。

## 服务端边界与失效处理

- 所有项目、修订、任务和结果绑定内部用户 ID；服务端逐次验证归属，不能依赖前端隐藏按钮。首版不提供公开项目 URL、分享令牌或跨用户协作 API。
- 计算器只接收持久化修订的快照和规范化请求；API 保存现有 `project_fingerprint`、`input_fingerprint`、`request_fingerprint` 及方法版本。保存输入和计算是两个明确动作；未保存编辑不能悄悄进入一次正式计算。
- 队列限制单用户同时运行数、项目大小、速度网格和总计算时间；运行失败、取消、部分结果、方法越界分别呈现。底层诊断代码、阶段、来源路径和消息保留，不合并相同文字。
- 邮件发送不可用时明确告知用户稍后重试，不能产生已登录状态。验证码错误反馈不披露账号是否存在。计算服务不可用时既有项目和历史报告仍可读取。
- 部署凭据、邮件服务密钥和服务器访问方式不属于设计稿。现有广州实例与未备案域名的公开接入、HTTPS 和实际邮件投递能力在部署阶段按真实域名核验；不把浏览器“不安全”提示视为备案状态。[腾讯云备案说明](https://cloud.tencent.com/document/product/243/18907) · [Chrome 连接安全说明](https://support.google.com/chrome/answer/95617)

## 设计验收

- 给定解析方箱、通用船和 Queen Mary 代理三个案例，用户能从项目库进入当前工况、保存并重开，运行或查看记录，并找到每个摘要值的单位、来源与适用性。
- 对 `0`、未知、估算、`not_requested`、`unavailable`、`model_limit`、`failed` 和 `canceled` 分别制作可区分的页面状态；不存在用空白卡片或绿色完成标记掩盖限制的情况。
- 两个不同账号即使知道彼此项目 ID，也无法通过页面或 API 读取、修改、计算或导出对方数据。邮箱验证码过期、复用与频繁请求的反馈清楚且不会泄露用户是否存在。
- 在桌面常见分辨率、窄屏报告、浅色、深色、键盘操作和黑白打印下检查层级、截断、焦点与状态识别。主题切换不改变计算结果或项目文件。
- 站内报告与 JSON/CSV 指向同一不可变计算记录，保持数值、单位、诊断和来源一致；任何格式都不把工程代理写成史实认证。

设计稿已用浏览器在 1440×900 渲染并目视检查两个主题。所列文字色与面板色的抽样对比度：浅色主文字 14.79:1、次文字 5.00:1、主操作文字 5.80:1；深色分别为 13.59:1、6.99:1、6.89:1。这是设计色样的核对，不替代实际组件、焦点和窄屏的可访问性测试。

本稿获批后再制定分阶段实施计划；此前不修改计算核心、主资产仓库、Unity 工程或服务器。
