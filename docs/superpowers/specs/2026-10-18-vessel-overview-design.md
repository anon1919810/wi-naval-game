## Facts and authority

Support native result schema `plimsoll-ship-design-result-1`, method `ship-design-native-v1`. The result has no project_id; Workbench already enforces project scope before passing its saved baseline. Require matching method and basis for highlights. Saved report parent gates requested/completed stage and run identity as today. Unsupported/absent results say why and do not draw/export numbers.

`guns.groups` is indexed by explicit integer `bank` 1..5 / id gunN, not array order. Ambiguous duplicate or mismatched identity is unavailable, not silently assigned to another bank. Read normalized native outputs; never recompute the source event chain or build mount counts from a selector in the UI. Keep zero, null/missing, invalid enum and invalid negative counts distinct; a missing value is not zero. Do not round fractional counts into a plausible physical arrangement. Prefer a bounded count label and abstract mount glyphs, never allocate one DOM node per source mount count.

Each battery displays barrels, total mounts, calibre, gun/mount type, year and calibre-length; G1/G2 layout, selector, actual per-mount barrel count, returned total mounts and elevated/deck/depressed counts; declared/effective projectile weight, rounds per gun and source gun/mount/ammunition/armour estimates. Add face, side/roof and barbette thicknesses when available. Actual `selectorG1/G2` (15 choices) and `perMountG1/G2` must remain separate; selectors with equal barrel count can have different meaning. Native `superSuper` and `subSub` flags are declarations, not coordinates. Source layout 0..18 labels come from `sship_fields.LAYOUT_LABELS` (18 is None), gun/mount enums and the 15 selectors from the existing catalogue. Preserve every distinct option, including None versus unknown; curate complete Chinese/English copies. No real station, orientation, firing arc, clearance, coverage or CG is inferred from empirical `positionG*`/`freeGunG*` fields.

Normalized calibre, armour thickness are **inches** irrespective of source page units. Print in/mm explicitly. `shellWeightDeclared`, `shellWeight`, `autoShellWeight`, `broadsideWeight` are **pounds**; retain explicit lb labels. Returned gunWeight, mountWeight, magazineWeight, armWeight and totalWeight are **long tons**, not metric tonnes: use existing display conversion `units.text(value,'mass','long_ton')` once and label these as source estimates. `totalWeight` is the source returned total, do not reconstruct it from fields. The source field is `gunN_turret_bottom_armour`, but the recovered expression treats it as barbette thickness; use clear source-aware wording.

Global selected/estimated masses and estimated/declared policies come only from `ledger.roles` (`guns`,`mounts`,`ammunition`,`gun_armour`) in metric tonnes and `balance`. No per-battery selected mass exists: do not split global ledger roles among five batteries, and never add source estimates to ledger totals. A manual mass policy change must remain visible in the overview/armament ledger even if source battery configuration is unchanged.

Overview reads normalized `hull.length/beam/draught` and `freeboard.freeboard` in ft, `engine.speedMax/speedCruise` in kn, `engine.hpMax` as labelled source hp, `engine.range` in nmi. Do not relabel source hp as canonical kW. Armour summary reads declared main-belt/deck thicknesses and coverage choice. Armament overview uses the five battery readings; no frontend recomputation of engineering totals. Performance scores, if shown, remain labelled empirical source scores; this increment need not add scores. Propulsion strings are source English descriptions; prefer localized native boolean selectors fuelArray/engineArray/driveArray where available, never guess a missing array.
