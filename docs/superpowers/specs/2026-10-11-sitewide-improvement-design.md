## 目标与取舍

把当前网站整理为一套连贯的研究工具体验：访客能理解能力，使用案例完成第一次计算，找到并修改输入，读懂有依据的结果，比较设计或损伤试验，并保存可复核的资料。

本轮以现有视觉语言、计算核和数据契约为基础，优先解决使用上的断点。Codex 建议按“全站语言一致 → 操作效率 → 结果解释 → 试验对照 → 整体验收”的顺序实施。新增功能限于项目检索、章节定位、报告对照整理和损伤试验研究流程。

## 设计决策

### 1. 语言是一项全站偏好

复用当前英文默认和已保存偏好，右上角语言开关覆盖总站、工作空间和实验室。切换语言是原地更新，不重新建立身份、不导航、不重新请求计算，不重置表单、滚动、选中项、回放、镜头、主题或声音。

双语覆盖应用自己编写的标题、按钮、表单标签、说明、空态、错误提示、对话框、无障碍名称、打印标题及新增功能。建立简短的中英术语表，固定“项目、修订、工况、运行、试验、未请求、未知、不适用”的对应关系。

用户输入的名称、原始证据、引用、JSON 字段、诊断码和接口枚举保持原文。已知诊断码可增加经审核的本地化解释，原始消息仍可展开；未知诊断提供本地化通用说明并展示原文，不根据字符串猜译。全文清单应明确区分这些例外。

按总站、工具和实验室组织文案，保持目前按路由加载的边界。新功能提交验收时同时具备中英文，避免收尾再补一遍。

### 2. 让已有操作容易找到

项目库增加按项目名检索，只过滤当前已读取集合；显示集合范围或返回数量，不暗示客户端拥有未加载的数据。空项目库与搜索无匹配有不同文案；清除搜索恢复列表。首次案例与备份恢复仍沿用现有入口。

工作台章节索引增加按标题/关键词过滤，使用现有章节 ID 和导航，不新增第二套定位协议。键盘可选章节、清空检索；切换章节不清除草稿。已存在的诊断按钮继续定位具体输入，不另做全字段搜索系统。

整理工作头和当前操作说明：让用户看见正在编辑哪个修订/工况、哪些更改未保存、此次请求哪些阶段、运行为什么暂不可用。复用当前就绪与诊断组件，不在浏览器中推算物理准备度或把“未评估”变成“通过”。

失败时保留输入和真实状态，提供明确的重试、返回或备份行动。读取重试不重复创建项目，保存/运行不自动重放；“请求取消”和服务端“已取消”继续区分。

### 3. 报告便于阅读，也便于复核

继续使用当前保存的结果和六项摘要读数。整理常用指标的友好名称、单位、有效性和来源；技术字段及原始证据可展开查阅。优先指标组包括载荷/排水量、吃水/横倾/纵倾、稳性、动力/阻力/续航；是否出现取决于真实请求和保存结果。

报告对照明确列出两次运行的项目、修订、工况、请求阶段、方法版本和结束状态，使用固定指标注册表与分组，取消按对象遍历顺序取前 8 项的限制。相同项目的不同修订允许研究对照，但必须显示输入差异和修订差异。方法、维度或阶段不兼容时显示理由，不给误导性数值差。

只对双方有效且可比的保存数值计算差值。未知、未请求、失败、不适用和真实零分别显示。不用百分比差制造零分母结果，不从缺失输入猜测因果，不重算物理量。读取另一个报告不改变当前结果、显示单位或编辑草稿。

打印内容和网页选择保持一致，新增应用标题使用当前语言。JSON/CSV 保持既有机器契约和规范单位；本轮不增加 AI 总结服务或新的整体报告格式。

### 4. 损伤实验室变成能解释差异的试验工具

采用 [损伤实验室对照提案](../plans/2026-10-11-damage-lab-comparison.md) 的三项增量：

1. **舱壁遮挡、部分透过、海水破口**三种明确标注的合成预设。遮挡组保持位置、强度、范围、seed 和 128 条代表性采样相同，只改变共有舱壁透过率 0 → 0.35。预设仅生成草稿，运行仍由用户发起。不能套用到不兼容的自定义布局。
2. **两次已完成试验的 A/B 对照。** 同项目、同修订、同工况和方法才进入受控数值对照；列出全部变化的试验输入。多变量、seed/采样数不同、时长或实际接受终点不同必须说明，不能把差异归因于某一面舱壁。两个相同旧修订的记录仍可只读对照。
3. **从证据解释损伤。** 点选模块、人员组或破口时，说明直接作用、遮挡/透过、机械损失、进水失效和人员不足分别怎样影响最终状态。连接到真实路径、界面及接受事件，不生成无依据的完整物理故事。

新增部分保持既有游戏近似和计算核结果的边界。代表性采样数不是实弹片数；开孔是声明的液压代理，不是穿甲结论；人员状态是聚合游戏估算。人员/功率未知时不填零；多破口共同造成的水量不能全部归给一个孔。回放在起爆前不能提前展示起爆后损伤。

选择 A/B、切换语言及推进事件不移动镜头、不替换当前草稿；只有显式“查看该试验”或“定位”触发相应动作。与最新修订不符的旧试验可读证据，但不能悄悄覆盖当前项目。

### 5. 视觉、声音和性能保持统一

保留 Space Grotesk / Inter、现有瑞士网格、左对齐、蓝色预览和红色 i 点、已接受的圆形转场、手动主题与五类音效。装饰继续服务于空间层级；本轮不新增装饰体系、不重新设计声音、不添加滚动劫持。

统一操作区、说明文字、分隔线、错误和加载状态的尺度与留白。以 390 / 768 / 1024 / 1440 / 1920 宽度检查：页面本身不横向溢出；密集表格可在明确的容器内横向滚动；实验室窄屏按配置、视图、检查信息排列，不强行压缩桌面三栏。

核对键盘路径、可见焦点、语言切换后的长文本、深浅主题、减少动效、关闭声音，以及 WebGL 不可用时的已有文字检查路径。连接错误、空态、资源失败必须给可用行动，不用假进度掩盖未知状态。

开始和结束分别记录同一环境下的构建体积、首屏请求与传输、关键交互及三维帧耗时。针对测到的主要开销优化，最多选择三项有实测收益的性能改动；没有证据的重构不占本轮。保持音频未启用不预加载全部音效、公开路由不提前装载三维模块、离屏动画及三维资源正确清理。首次大小预算以执行时基线为准，增长须注明功能来源，不能只为清除 bundle 警告拆包。

- 不改变计算核算法、方法身份、项目和报告格式、冻结运行、规范单位、未知值语义与当前结果身份保护。

- 不使用真实用户项目做破坏性验收；本地专用案例和数据库负责创建、修改、计算及恢复流程。

## 完成标准

1. 已列出的全站应用自有文本有自然、完整的中英文；默认及保存偏好正确，语言切换不丢状态。
2. 新访客可沿现有引导完成案例创建、保存修订、运行、读报告、修改重算和备份恢复；检索及章节定位可用。
3. 报告对照有稳定的指标组、身份和差异说明，未知或不兼容数据不会显示成有效改善。
4. 三个实验室预设、受控 A/B 和证据解释可用；保持核心数值、冻结输入、镜头与回放契约。
5. 全站列出的尺寸、主题、键盘、减少动效与无 WebGL 路径通过本地人工检查；性能改动有前后证据。
6. 相关测试簇、生产构建和差异检查通过；交付本地链接、截图/操作记录、改动清单、剩余限制及待发布清单。
