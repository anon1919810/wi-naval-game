# F4: 舰队/大型载具游戏 LOD 档位实践

## Findings

### [1] Unity LOD Group authoring hard-caps at eight levels and uses screen-height percentage (not world distance) as the switch metric; Object Size remaps those percentages into meters.
- quote: "The LOD Group component accepts a maximum of eight LOD levels. Unity uses LOD 0 closest to the camera, so it should be the most detailed LOD level." / "Object Size: Sets the size of the object in meters for LOD Group calculations. For example, if you change Object Size from 1 to 0.6, an object that has a screen height of 100% is now considered to have a screen height of 60%. As a result, the transitions to smaller screen height percentages and less detailed LOD levels occur closer to the camera."
- url: https://docs.unity3d.com/Manual/lod-group-configure.html ; https://docs.unity3d.com/Manual/class-LODGroup.html
- source_type: primary
- published: unknown (Unity 6.6 docs, built 2026-09-16)
- confidence: high

### [2] For ~213 m capital ships, mis-set Object Size is the main wrong-distance pitfall: LOD Group transitions are authored as % screen height, and Object Size changes where those thresholds land in meters.
- quote: "Sets the height of the object when the LOD level transitions to the next LOD level, as a percentage of the screen height. To the right of this property, Unity displays the camera distance at which the LOD level transitions, in meters."
- url: https://docs.unity3d.com/Manual/class-LODGroup.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [3] Project-wide LOD Bias rescales all LOD transition distances; bias > 1 keeps higher detail longer, bias 0–1 drops LOD earlier (bias 2.0: a 50% threshold fires at 25% distance).
- quote: "A LOD Bias value between 0 and 1 results in Unity selecting lower-quality LODs at closer distances than normal. A value of 1 or more results in Unity selecting lower-quality LODs at farther distances than normal, so GameObjects retain higher quality for longer. For example, if you set LOD Bias to 2, a transition to a lower-quality LOD level that usually happens at 50% distance now happens at 25% distance (50% / 2 = 25%)."
- url: https://docs.unity3d.com/Manual/class-QualitySettings.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [4] Unity Mesh LOD auto-generation halves index counts per level, needs ≥256 source triangles, and is poorly suited to warships: it "might produce undesired results on meshes with a high curvature or meshes that consist of many disconnected pieces."
- quote: "Each subsequent LOD contains approximately half the number of indices as the previous one." / "The original mesh must have at least 256 triangles for the simplification process to start." / "The generator works best for organic shapes or relatively flat surfaces with a high vertex density, for example: living creatures, rocks, sculptures, and so on. The generator might produce undesired results on meshes with a high curvature or meshes that consist of many disconnected pieces."
- url: https://docs.unity3d.com/Manual/lod/mesh-lod-generator.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [5] For fleet screens, LOD Group is the better authoring path than Mesh LOD because LOD Group can also drop materials/submeshes (draw calls) per level; Mesh LOD only reduces triangles and is not recommended combined with LOD Group.
- quote: "When authoring LOD objects, you have the following optimization options for each LOD: Create a less detailed mesh. Reduce the number of materials or submeshes, which reduces the number of draw calls. Optimize settings on materials. Optimize Mesh Renderer settings." / "Using Mesh LOD in combination with LOD Group might lead to unexpected outcomes and is not recommended."
- url: https://docs.unity3d.com/Manual/LevelOfDetail.html ; https://docs.unity3d.com/Manual/lod/mesh-lod-introduction.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [6] URP LOD Cross Fade is a pipeline-wide toggle with three dither modes (Bayer Matrix faster/repetitive, Blue Noise better-looking/slightly costlier, 2x2 Stencil significantly fewer shader variants); per-LOD Fade Transition Width e.g. 0.4 means the fade occupies 40% of that LOD's screen-size range.
- quote: "LOD Cross Fade Dithering Type ... Bayer Matrix: better performance than the Blue Noise option, but has a repetitive pattern. Blue Noise: uses a precomputed blue noise texture and provides a better look than the Bayer Matrix option, but has a slightly higher performance cost. 2x2 Stencil: Unity uses bits 4 and 8 in the stencil buffer to apply a 2 × 2 dithering pattern, instead of alpha testing. This setting significantly decreases the number of shader variants." / "if you set the Fade Transition Width of LOD0 to 0.4, the transition to LOD1 occurs over 40% of the LOD0 range."
- url: https://docs.unity3d.com/Manual/urp/universalrp-asset.html ; https://docs.unity3d.com/Manual/lod/lod-transitions-lod-group.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [7] URP GPU Resident Drawer (BatchRendererGroup instancing) is most effective when many GameObjects share the same mesh and material shader variant—exactly the 15-identical-ships case—but slightly increases GPU work and can increase overdraw on desktop/console.
- quote: "Multiple GameObjects use the same mesh and the same material shader variant. As a result, Unity can group them into a single draw call." / "GPU Resident Drawer improves CPU performance, but it slightly increases GPU workload. ... When using GPU Resident Drawer, consider the following: GPU draw call performance ... Overdraw: Merging objects into a single instanced draw call can lead to increased overdraw, particularly on non-tiled GPUs commonly used in desktops and consoles."
- url: https://docs.unity3d.com/Manual/urp/gpu-resident-drawer-performance.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [8] GPU Resident Drawer does not support LOD Group animated cross-fading (falls back to static distance-based cross-fade) and requires Forward+/Deferred+; incompatible renderers (MaterialPropertyBlocks, >128 materials, certain light-probe modes) silently fall back.
- quote: "LOD Group animated cross-fading: Animated cross-fading transitions are not supported. LOD transitions fall back to static, distance-based cross-fading." / "A render pipeline asset containing only Renderers using the Forward+ or Deferred+ rendering paths." / "Uses no more than 128 materials."
- url: https://docs.unity3d.com/Manual/urp/gpu-resident-drawer.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [9] URP Small-Mesh Screen-Percentage culls objects below a screen footprint and "might not work if you use your own Level of Detail (LOD) meshes"; set to 0 to disable, or add Disallow Small Mesh Culling per GameObject—critical when fleet cameras pull far out and ships still must stay selectable/visible.
- quote: "Small-Mesh Screen-Percentage: Set the screen percentage Unity uses to cull small GameObjects, to speed up rendering. Unity culls GameObjects that fill less of the screen than this value. This setting might not work if you use your own Level of Detail (LOD) meshes. Set the value to 0 to stop Unity culling small GameObjects. To prevent Unity culling an individual GameObject that covers less screen space than this value, go to the Inspector window for the GameObject and add a Disallow Small Mesh Culling component."
- url: https://docs.unity3d.com/Manual/urp/universalrp-asset.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [10] Per-layer Camera.layerCullDistances (32-float array; 0 = use far plane; optional spherical mode) is Unity's official lever to cull small objects earlier than the far plane—usable for rigging/AA/detail layers on distant capital ships while keeping hull LOD longer.
- quote: "Normally Camera skips rendering of objects that are further away than farClipPlane. You can set up some Layers to use smaller culling distances using layerCullDistances. This is very useful to cull small objects early on, if you put them into appropriate layers. When assigning layerCullDistances, you need to assign float array that has 32 values. Zero values in cull distances means \"use far plane distance\". By default, per-layer culling will use a plane aligned with the camera. You can change this to a sphere by setting layerCullSpherical on the Camera to true."
- url: https://docs.unity3d.com/ScriptReference/Camera-layerCullDistances.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [11] Discrete LOD's documented trade-offs for multi-instance assets are storage for multiple full model copies plus visual "popping" at transitions—both scale poorly when many capital ships share a frame; continuous/hierarchical approaches exist as research alternatives to discrete swaps.
- quote: "Traditionally, LoD is implemented using discrete levels (DLoD), where multiple, distinct versions of a model are swapped out at different distances. This long-standing paradigm, however, suffers from two major drawbacks: it requires significant storage for multiple model copies and causes jarring visual \"popping\" artifacts during transitions, degrading the user experience."
- url: https://arxiv.org/abs/2510.09997
- source_type: primary
- published: 2025-10-11 (v1); 2026-04-01 (v2); ICLR 2026 poster
- confidence: medium

### [12] Unity's own multi-object guidance says when many GameObjects are on screen at once, reduce polygon count per mesh; GPU-side vertex count is usually higher than DCC reports because vertices split at normals/UVs/color seams (common on hard-surface ships).
- quote: "If you have a lot of GameObjects or Terrain objects on screen at the same time, consider reducing the polygon count per meshes. ... the actual number of vertices that graphics hardware has to process is usually not the same as the number reported by a modelling application. ... some geometric vertices need to be split into two or more logical vertices for rendering purposes: for example, a vertex must be split if it has multiple normals, UV coordinates or vertex colors. Consequently, the vertex count in Unity is usually higher than the count given by the 3D application."
- url: https://docs.unity3d.com/Manual/ModelingOptimizedCharacters.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high

### [13] Maximum LOD Level strips LOD meshes below that index from builds (smaller build/runtime memory); Addressables-packed models ignore this and always ship every LOD mesh—relevant when many ship LOD chains are addressable.
- quote: "Maximum LOD Level: Sets the lowest LOD level the project uses. Unity removes LOD meshes below the Maximum LOD level from the build, which makes the build smaller, and reduces memory use at runtime. ... Note: If a model is included in Addressables group, Unity adds the entire model including all LOD meshes in the build, regardless of the Maximum LOD level property."
- url: https://docs.unity3d.com/Manual/class-QualitySettings.html
- source_type: primary
- published: unknown (Unity 6.6 docs)
- confidence: high
